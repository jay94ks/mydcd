## 앱 선언과 tenant 관리 변경

| 명령 계열 | 적용대상 | 입력/선택 | 효과와 경계 |
|---|---|---|---|
| `app check` | 로컬 앱 문서 | 명시 `-f` 또는 유일한 기본 파일 | app 문법/정규화 확인. 원격 이름 해석/권한·native 준비 성공은 아님 |
| `app diff` | 선택 tenant의 이름 있는 앱과 현재 관리 자원 | app.yaml 또는 --source-operation의 원 문서/보존 사실·현재 snapshot/catalog | 배치·이름 참조·차이 검사. lifecycle 원문은 app 선언이고 사전 staging한 SourceFact는 별도 plan metadata다. 계획 자체는 원문 저장/named 등록/compiler 기동을 하지 않는다. 제출/실제 생성 없음. 관리 자원 정의를 앱에서 수락하지 않음 |
| `app deploy` | 선택 tenant/app의 고정 목표 | app.yaml/승인된 plan·명시 operation | inline이 있으면 preflight 뒤 원 문서/provider parent·source child를 보존하고 cache를 준비한 뒤 같은 daemon Inventory/Execution으로 수락·진행. 일반 반복은 원 결과 확인이며 파일 재읽기/자동 전송을 하지 않음. 미정산 앱 이관의 원 Inventory는 다른 upload/operation으로 교체할 수 없음. 취소/완료 뒤에는 현재 권한과 새 Task 세대로 진행. 기존 관리 network/Volume/Secret을 빌리며 별도 관리 설정을 자동 적용하지 않음 정책 재시작은 같은 operation/Task/native의 owner 서명 StartedAt/TaskRestart 보고로 정산하며 새 관리 operation/native ID를 합성하지 않음. |
| `app list/show, app deploy·down의 대기` | 현재 또는 원 tenant/app/operation | 명시 app/operation·원 기록 | Desired/Applied/Observed·원 진행 조회/대기. wait 만료는 미실행/최종 실패 증거가 아님 |
| `op resume` | 원 앱 operation | 저장된 원 intent/ID/artifact | source 준비 또는 원 app 결과 정산/명시 재개. 시도된 source 재전송은 positive missing 뒤 --retry-source만 허용. 새 프로필·파일·CAS로 바꾸거나 자동 새 ID를 만들지 않음 |
| `app down` | 선택 tenant/app의 소유 inventory와 사용 참조 | 원 수락 선언의 DownTarget·명시 operation. 요청은 Target을 서명하고(down CAS 경계는 서버가 Change로 정한다) 원 expected/root를 보존 | 관측 갱신은 종료 대상을 바꾸지 않음. 새 Origin/다른 종료·미래 좌표·현재 cleanup 권한 부재는 거부. 앱 컨테이너/Ingress·앱 소유 자원 정산, 빌린 망/Group/기존 Volume은 참조 반환. retained 데이터 삭제 없음. 과거 strict 요청을 재서명/새 모드로 바꾸지 않음  원 Task의 grace/signal·StopSent/원 Start checkpoint를 보존하고 API timeout 뒤 새 Stop/ID로 바꾸지 않음. 실제 종료/Gone과 writer fence를 별도 확인. |
| `network create/update/delete -f network.yaml` | **한 tenant**의 TUN 망 하나 | network.yaml·작업 ID·단계별 고정 ID와 각 typed 변경의 CAS | 파일대로 create-tun-network·configure-network-dns, 주소·서버 변경은 plan→drain→closure→fence→commit/reconfigure. 끊기면 `op resume`. [mydc network](../../cli/network.md) |
| `route propose/approve/withdraw` | 두 tenant 사이 route 하나 | Networks/route revision CAS | 양측 승인 뒤 열림, 한쪽 withdraw로 닫힘. [mydc route](../../cli/route.md) |
| `manage apply` | typed action이 지정한 자원 | JSON typed 관리 변경·원 operation | 아래 권한표에 따라 현재 handler가 검증. 파일 형식/CLI 이름이 권위를 만들지 않음 |
| `manage result/resume` | 원 typed operation | 저장된 원 요청 | 원 결과 조회/명시 재개. 다른 tenant/actor의 작업으로 교체하지 않음 |
| `manage prune` | 로컬의 정산된 옛 operation 기록 | 현재 서버에서 확인한 submitter epoch·원 profile | 정리 가능한 로컬 기록만 회수. Raft log/DB/원 native 삭제나 서버 epoch 회전 명령이 아님 |
| `manage apply`의 `put-registry` | 한 tenant/registry ID·고정 Volume scope·선택 node | ManageRegistry + ManageVolumes의 현재 session/node 허가·registry record와 root CAS | 전체 Spec 교체이며 Enabled를 명시. endpoint·저장/요청 예산만 공개 입력(TLS 인증서는 authority 호스트로 보관함에서 찾음). 개인키/host 경로·접속 자격/Ready를 넣지 않음. 원 Volume scope 교체·registry 생성에 따른 trust 자동 등록 거부 |
| `start-registry`, `stop-registry`, `delete-registry` / 원 `manage result/resume` | 명시 tenant/ID·원 record CAS/operation | start는 현재 두 관리 scope와 선택 node, stop/delete는 ManageRegistry cleanup | 시작은 새 현재 사용자 grant를 보존. stop은 desired만 내리며 실제 writer 반환을 뜻하지 않음. delete는 disabled/활성 예약 없음에서 정의 tombstone만 남기고 Volume 데이터 보존. 원 ID·CAS/서명 재생성 없음 |
| MYDCP `registries` 조회 | 명시 tenant·현재 Read session·동일 root의 페이지 | tenant와 after, RegistryPage를 사용하는 인증 client | 공개 Spec/세대/관측만 조회하며 원 사용자 서명·자격/개인키는 반환하지 않음. stale spec의 serving 관측을 현재 Ready로 표시하지 않음. 서버 Runtime/TLS 연결 전 관리 수락만으로 실제 동작을 주장하지 않음 |
| `registry list/show/wait NAME` | 선택 cluster/tenant의 현재 registry metadata | 현재 Read 계정·전역 선택 규칙. wait는 --until serving\|stopped\|deleted와 유한 --wait-timeout | 같은 root의 페이지를 합치고 active/draining·serving 관측을 구분. wait 만료는 원 작업/데이터를 취소하지 않음. serving은 보고 관측이며 외부 TLS/Engine probe 성공이 아님 |
| `registry login NAME --repository REPO [--push]` | 선택 계정·tenant/registry/authority/repository | 현재 session과 요청별 권한. catalog는 명시 --repository '**' --access catalog | FD>=3의 pipe/socket 또는 현재 UID 소유 private 파일로만 파생 login bytes 전달. stdout JSON에는 username/audience/scope/기한만 출력. 원 MYDCP proof/private key·계정 password를 전달하지 않으며 자격을 Raft/앱 파일/원 operation에 저장하지 않음 |
| MYDCP `registry-image-permit` | installed Task owner·원 Task/Binding/고정 이미지 | latest quorum·AppBindingPermit의 원 수락 grant/현재 권한·tenant image trust | 설정 해석/pull·cached image·Create/Start 경계. 사용자 session 만료를 새 로그인으로 대체하지 않음. 내장 registry는 현재 run/tenant/writer와 serving 관측 필요. 다른 tenant·중지/철회 source의 익명 fallback 거부. 반환은 공개 scope/barrier이며 secret은 포함하지 않음 |

| MYDCP `registry-credential` | 현재 user session과 명시 tenant/registry/repository·pull/push/catalog | 기존 login의 서명 proof·현재 권한과 live 원 registry run | 별도 domain/audience의 짧은 파생 자격을 보호 사용자 wire로 반환. Raft/일반 관리 출력에 저장하지 않고 MYDCP session을 OCI bearer로 사용하지 않음. 사용자 CLI의 보호 전달과 앱 Task-bound pull은 별도 소비 경계 |

| `approve-route` | Tenant에 지정한 관련 한쪽의 현재 ManageRoutes/node scope. SourceTenant/ID와 원 route revision CAS | 양쪽의 명시 승인·현재 source 승인자 권한·consumer 한도를 검사하고 최종 승인은 양측 instance/불변 Bridge dependency와 같은 FSM으로 게시. 관리자도 양쪽을 별도로 승인. 실제 native Ready와 구분 |
| 내부 `route-work` | authenticated Member인 실제 local owner의 원 Reference ID·At와 latest quorum. 사용자의 raw native 입력이 아님 | 원 참조/peer·불변 TUN 정책·현재 한도/PrepareAllowed의 준비·정리 조회. 소비 시 quorum epoch/root·로컬 재계산 결과를 일치시킴. native effect 허가/Started/Ready를 주장하지 않고 권한 회수 뒤 원 기록 보존. legacy gateway는 새 route 입장 거부·명시 native 전환 요구 |
| 내부 `route-flow-observe` | authenticated Member인 자기/원 반대편 owner가 해당 native owner에 Latest=false로 직접 요청. 입장은 별도 latest quorum·원 native 확인, Close는 local committed 원 참조의 cleanup | 원 native proof·pin 조회/결합과 실제 IO/path PacketReady 관측(입장/서비스 Ready 아님), Native+Tuple+Receipt의 destination 원자 입장. Close+Tuple은 원 claim의 Closing→IO barrier/native drain→pin 반환/tombstone 또는 미입장 봉인과 영구 Closed 서명. 실제 DB read-back 뒤만 응답하고 source는 양측 정산 뒤 원 pin 반환. 응답 유실은 같은 원 claim/pin으로 재개. CloseQuery=true는 기존 tombstone read-back/서명만 하며 봉인/반환/native/gate를 변경하지 않음. missing journal/legacy 불명은 미입장 아님. 새 입장/Ready·source pin/native 재생성·IP packet stream 우회는 거부 |
| 내부 `route-dispatch` | 실제 local owner가 내구 저장한 원 Reference/Bridge·journal digest·boot·Apply1·policy/native hash의 서명과 Apps root CAS/module epoch | 같은 Authority의 변경 불가 dispatch 표식. 재전송은 원 제출/결과를 보존하고 Applied/Gone·새 flow를 주장하지 않음. 높은 확정 epoch와 원 영구 사실 부재를 함께 입증한 경우 봉투만 갱신 |
| 내부 `route-native-permit` | authenticated Member인 실제 local owner의 Reference·원 private nonce·operation1·At와 latest quorum | 원 공유 표식 및 현재 양측 정책/Bridge/한도를 재검사하는 첫 Apply 허가. 새 journal/nonce 생성이나 native 성공 관측을 대신하지 않음 |

| `fence-network-change` | 원 변경 generation/revision·Resources root CAS·원 member의 NetworkClosure·현재 ManageNetwork cleanup scope | 같은 Authority/Book의 주소/참조·Drain/서명을 확인해 해당 change를 fenced로 저장하고 종료된 member source만 tombstone으로 철회. 다른 member/새 target은 게시하지 않고 native proof는 관리 명령에 넣지 않음 |

관리 명령이 지원하는 typed action은 [입력 명세](../app-and-cluster-spec.md)와 실제 whitelist를 따른다. 위 범주는 장기 책임 분류이며 모든 action이 이미 관리 명령에 연결되었다는 뜻이 아니다. 미지원 action은 제출 전에 거부한다.

내장 cmd와 사용자 Probe.Exec는 원 run의 Target/명시 capability·현재 Task 권한에만 적용하며 원 observation의 exec 전송 receipt를 사용한다. 새 사용자 관리 명령·Docker 제어 권한을 만들지 않고 불명 뒤 같은 exec의 조회/정산만 수행한다.

compiled checker의 로컬 Probe/결과는 부모가 전달한 전용 FD3/FD4를 사용한다. 호출별 경로 socket이나 사용자용 내부 실행 명령을 추가하지 않는다. Yaegi는 같은 SDK의 guarded Probe를 직접 소비한다. 두 경로 모두 원 run/Task와 현재 권한을 확인하며 관리 접속 기본 `/var/run/mydc.sock`과 구분한다.
