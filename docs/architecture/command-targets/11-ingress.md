## Ingress 운영과 인증서

| CLI / API | 인증·대상 | 원 결과·효과 |
|---|---|---|
| `ingress list/show/metrics/errors/blocks` → User `ingresses` | 현재 사용자 Read tenant/node; `--all`도 현재 credential 범위만. owner member `ingress-observe`는 원 사용자 Session을 재검사 | mapping/실제 snapshot·60초 계수·가린 오류·적용 기록. 노드 수신 주소 요약은 보이는 shared listener를 한 번씩 계상. BlockRevision은 정책 book 목표, Runtime.BlockRevision은 같은 단위의 owner 설치 revision이다. RootRevision/블록별 CAS와 구분하고 목표 ID 부재만으로 해제 완료를 판정하지 않음. query는 Task/Desired를 변경하지 않음. [형식](../../reference/ingress-management.md) |
| `ingress block/unblock/extend` → typed `ingress-block/ingress-unblock/ingress-block-extend` | tenant ManageNetwork·현재 operation ceiling. node/tenant/gateway·cross-tenant host는 시스템 관리자. 여러 tenant 조회는 `--all` | 별도 Raft block 기록·record CAS·원 사용자 operation/journal. 만료는 레코드 삭제가 아님. 같은 `--id`의 재실행·`sfcli op resume`은 원 입력만 재개 |
| `ingress gateways show/set NODE` → User `ingresses` Part=gateways / `set-node-gateways` | 현재 시스템 관리자·명시 node. 변경은 대상 owner의 현재 주소 preflight evidence와 record CAS | 원 gateway claim·사용자 operation을 Raft에 보존. 파일/클러스터 목표·AppliedRevision/Error 구분. 앱·단독 `ports:`와 실제 listener 충돌 검사 |
| `ingress balance/drain/undrain` → `set-ingress-balance/drain-ingress/undrain-ingress` | 현재 tenant Network 관리 권한, 선택 tenant와 입력 일치, item CAS(기본은 읽은 값, `--if-revision`)·원 작업 ID | 관리 overlay만 변경하며 Task/container/native generation 보존. 진행 flow는 drain deadline까지 유지하고 기한에 취소. 같은 `--id`는 원 입력 |
| `ingress history` → User `ingresses` Part=history | 현재 tenant/node Read, 시스템 전역 조회는 ManageCluster. app/node/tenant·사용자/현재 권한에 cursor 결합 | 원 At/Actor/Request와 공개 Detail/Previous 최신8행. 승인/Session 원문·비밀 제외; 실제 적용 완료와 구분 |
| `ingress hosts show/set` → `set-ingress-host-policy` | 시스템 관리자·명시 tenant 대상. 현재 tenant profile과 입력 Tenant 일치 | tenant host 권한의 item CAS. 기존 앱 참조 보존, 새 native/실제 gateway는 현재 정책 검사 |
| `vps account list` → User `vps` | 시스템 관리자·현재 credential read ceiling(`vps`) | 계정 이름·종류·트래픽 단가·액세스 키 끝 네 글자. 봉인한 키 없음 |
| `vps account add/rotate-key/set/remove` → `put-vps-account`/`remove-vps-account` | 시스템 관리자(`ManageCluster`)·동작별 ceiling. add/rotate-key의 시크릿 키는 SecretInput `Mode:vps-credential`로 투표 서버가 봉인 | payload `VPSAccountPut{Name,Vendor,OverageKRWPerGB,Credential?,SSHKeyID?,Guard?}`/`VPSAccountSelection{Name}`, CAS는 계정 목록 전체 revision. 봉인한 서버는 현재 투표 서버, 봉인의 Request는 그 작업 ID여야 함. 새 계정은 Credential 필수, 종류는 바꿀 수 없음. SSHKeyID는 Credential 없이 보낼 때마다 바뀜(봉인에 SSH 공개키가 있어야 함), 새 Credential이면 지워짐. 최대 32개 |
| `vps create` → `create-vps-node` | 시스템 관리자(`ManageCluster`)·동작별 ceiling | payload `VPSServerCreate{Name,Account,Zone,Image,Flavor,Script?,SSHKeys?,CapKRW,CapAction?,Voter,Port}`(`CapAction` ""=상한 넘으면 끄기, `notify`=알림만), CAS는 같은 목록 revision. 계정이 있어야 하고 이름은 기존 서버·genesis·다른 VPS와 겹치면 안 됨. SSH 키는 정렬·중복 없이 최대 4개, 최대 64대. Script가 없으면(SSH 설치) 계정 SSHKeyID가 SSHKeys에 있어야 함. 계정에 VPS가 남아 있으면 `remove-vps-account`는 ConditionFailed. 이후 단계는 리더(투표 서버)의 `vps-report`(ModuleReport, 키 `control/vps`)로만 바뀜: `create-sent`(만들기를 보내기 전 한 번만, `creating` 유지) 뒤 `creating`→`installing`(인스턴스 ID·공인 IPv4·리더 빌드 SHA-256) 또는 `failed`(이유 코드). 가입: ingress 멤버의 멤버 보고 `vps-enroll`(`Source`=연결 주소가 서버 공인 IP, `Peer`=이름·키·공인IP:포트, 투표권 없음)이 `control/members`에 초대를 만들고, 리더가 서명한 초대를 `vps-report invited`로 한 번 남김 |
| `vps stop` → `stop-vps-node` | 시스템 관리자(`ManageCluster`)·동작별 ceiling | payload `VPSServerStop{Name,DNSWaitSeconds}`(0~3600), CAS는 같은 목록 revision. 서버가 `running`이고, 정식 멤버이며 cordon되어 있고, 그 서버의 가장 최근 drain이 `Succeeded`여야 함. 투표 서버는 나머지 투표 서버가 한 대 더 잃어도 quorum이 남을 때만. 단계 `stopping`(`PowerRequest`=작업 ID, `StopAfter`=시각+DNSWaitSeconds). 리더가 `StopAfter` 뒤 끄고 꺼진 것을 확인하면 `vps-report stopped`(`At` ≥ `StopAfter`) → `stopped`. DNS 임시 변경(설계 5a, 웹)은 아직 없어 그 전까지는 사용자가 직접 뺀다 |
| `vps start` → `start-vps-node` | 같음 | payload `VPSServerSelection{Name}`. 서버가 `stopped`, 또는 `capped`이면서 `CapKRW` > `CapStop.ProjectedKRW`이거나 작업 시각이 `CapStop.Month`(KST)가 아닌 달이어야 함. 단계 `starting`. 리더가 켜고 실행 중인 것을 확인하면 `vps-report started` → `running` |
| `vps set-cap` → `set-vps-node-cap` | 같음 | payload `VPSServerCap{Name,CapKRW,CapAction?}`(1~100,000,000원, `CapAction` ""/`notify`). 서버가 있고 `deleting`이 아니어야 함 |
| (리더) 상한 중지 → `vps-report capped` | 투표 서버 리더 | 10분 감시에서 지금까지 요금이 상한을 넘거나, 1시간 이상 읽은 예상이 넘으면. `Cap:{At,Month,CapKRW,SoFarKRW,ProjectedKRW}`(At=보고 At, CapKRW=서버의 지금 상한, 넘은 값이어야 함). 서버가 `running`, `CapAction`이 ""이고 투표 서버면 한 대 더 잃어도 quorum이 남을 때만. drain 없이 `stopping`(`PowerRequest`=`cap-<Month>`, `StopAfter`=At+300, `CapStop` 기록) → 끈 뒤 `vps-report stopped` → `capped` |
| `vps delete` → `delete-vps-node` | 시스템 관리자(`ManageCluster`)·동작별 ceiling | payload `VPSServerSelection{Name}`, CAS는 같은 목록 revision. 서버가 있고 `deleting`이 아니어야 하며, 같은 이름의 멤버가 없거나 `invited`이거나 이미 제거됐을 때만(가입한 서버는 `node drain`·`node remove` 먼저, 아니면 ConditionFailed). 단계는 `deleting`(`DeleteRequest`=작업 ID). 리더가 인스턴스를 지운 뒤 `vps-report deleted`로 기록을 지움. 가입을 마치면 리더가 `vps-report running`(`installing`→`running`, 초대한 키가 정식 멤버일 때만). VPS 초대(`vps-` JoinID)의 가입 `dispatch` 멤버 보고는 서버가 `installing`일 때만 받는다(삭제 중이면 ConditionFailed) |
| `certificate list/show` → User `certificates` | 시스템 관리자·현재 credential read ceiling | 공개 metadata·상태·연결만, 보관함 revision 고정 cursor. `show`는 ID 조회로 공개 체인도 받음 |
| `certificate put/delete/disable` → `put-certificate`/`delete-certificate`/`disable-certificate` | 시스템 관리자·동작별 ceiling; put의 PEM/key 파일(또는 stdin)은 SecretInput `Mode:certificate` | 보호 입력 intent/원 sealed receipt→사용자 signed typed operation(`Expected` 0). 인증서는 ID로 고르며, 이미 있는 ID는 보내지 않음. 같은 `--id`의 재실행은 원 provider receipt와 서명된 원 operation만 이어 보냄 |
| `domain list` → User `certificates` 첫 페이지의 `Domains` | 시스템 관리자·현재 credential read ceiling(`certificates`) | 등록 도메인 전체(A-label·추가한 사람·시각)와 보관함 revision. 따로 query method는 없음. [도메인](../../cli/domain.md) |
| `domain add/remove` → typed `add-domain/remove-domain` | 시스템 관리자(`ManageCluster`)·동작별 ceiling | payload `DomainChange{Name}`(정규화한 A-label 또는 정규형 IP. 와일드카드·한 단어·공개 접미사·zone/미지정/멀티캐스트 IP는 Invalid), CAS는 인증서 보관함 전체 revision. 이미 있는 이름의 add나 없는 이름의 remove는 ConditionFailed. remove는 그 도메인 아래 호스트에 인증서 링크가 있어도 거절하지 않음(링크만 끊김). 최대 128개 |
| `domain acme-responder show` → User `certificates` 첫 페이지의 `ACMEResponder` | 시스템 관리자·현재 credential read ceiling(`certificates`) | 주소·설정한 사람·시각. 없으면 비어 있음 |
| `domain acme-responder set/clear` → typed `set-acme-responder` | 시스템 관리자(`ManageCluster`)·동작별 ceiling. 웹 자동화 계정은 이 동작을 위임받아 시작할 때 채움 | payload `ACMEResponderChange{Address}`(정규형 IP:port, 비우면 지움. 이름·port 0·zone·미지정·멀티캐스트는 Invalid), CAS는 보관함 전체 revision. 같은 주소를 다시 넣거나 없는 것을 지우면 ConditionFailed |
| member `CertificateMaterial=17` | 답하는 쪽은 마스터 키를 가진 현재 voter. Read는 현재 설치 ingress owner·정확한 goal revision/generation/ref/host, Seal은 WorkKey 멤버·키 소유 증명, Master는 현재 voter | 유도한 인증서 key(Read: 그 host에 연결된 인증서만, Seal: 아직 없는 업로드) 또는 마스터 키 공급. User/SecretFetch/Unix·relay·early data·datagram으로 우회 불가 |
