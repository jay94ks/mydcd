|---|---|---|---|

Unix 관리 주소와 서명된 노드 간 접속 주소를 같다고 요구하지 않으며 원격 pin은 기존 정확한 endpoint 대조 유지 |
| `node remove NODE`(가입 전) / `node add NODE --replace` → `cancel-node-invite` | 초대만 된 서버를 잊는다 | 현재 system admin, payload `NodeSelection{ID}`, CAS는 그 항목 revision | 항목이 `invited`이고 join이 Raft로 넘어가지 않았을 때만(작업이 준비 단계, native index·ack 없음). 항목과 cordon 행을 지우고 이름·키·endpoint·서버 주소를 푼다. 넘어갔으면 ConditionFailed(`learner` 이후는 가입이 끝난 뒤 drain·remove) |
| `node remove NODE`(learner) → `abort-node-join` | 설치 확인을 끝내지 못한 learner의 가입 포기 | 현재 system admin, payload `NodeSelection{ID}`, CAS는 그 항목 revision | 항목이 `learner`이고 ack가 없을 때만. 서명한 원본을 항목 `Abort`에 남기고 그 뒤 ack(`installed`)는 거절. 리더가 Raft에서 빼고(이전 index CAS) 커밋된 구성 index가 learner의 것보다 크고 서버가 없으면 멤버 보고 `join-aborted`(투표 서버만) → 항목·cordon 행 삭제, 설치된 구성 prefix와 토폴로지에서도 그 노드를 지움. 결과를 모르는 가입은 리더의 멤버 보고 `absent`(투표 서버만, 커밋된 구성 index ≥ dispatch index이고 서버 없음)로 같은 승인의 첫 작업으로 다시 준비되어 취소하거나 다시 가입할 수 있음 |
| `node set-endpoint NODE HOST:PORT` → `set-node-endpoint` + 서버의 `sfcd set-listen` | 가입한 서버의 IP·포트가 바뀌었을 때 주소만 옮긴다 | 현재 system admin, payload `NodeEndpointChange{ID, Endpoint}`, CAS는 그 항목 revision | 설치된 full member이고 진행 중인 멤버 변경이 없을 때만. 새 주소는 정규 HOST:PORT, 지금 주소와 다르고, 다른 서버의 주소나 옮겨 가는 주소가 아님. 투표 변경과 같은 원 작업(`Voting`, `Endpoint` 채움)으로 단계 `moving` → 리더가 같은 ID·새 주소로 AddVoter/AddNonvoter(이전 index CAS) → 설치된 구성을 본 `observe`로 항목 주소가 바뀜. 그동안 Raft 주소는 옛·새 주소 둘 다 그 서버로 인정. genesis 기록은 그대로. `sfcd restore`로 세운 서버는 거절. 서버 쪽은 설치 기록 `Listen`에 새 주소를 적고 자기 키로 다시 서명(sfcd 멈춘 상태) |

| `node remove-plan/demote-plan NODE` | 전역 노드의 실제 설치 voter 구성·원 owner 참조 | 현재 system-admin/ManageCluster. `Expected`·`Epoch`·members root/configuration index를 반환하며 조회로 예약하지 않음 | 제거·demote reducer가 같은 installed-membership 계산기를 재사용. 제거 계획은 accepted Tasks·고정/보존 Volume·등록 저장 root·shared 미정산 참조를 투영. 마지막 voter/예약 과반 상실/원 node operation·저장소 blocker를 같은 `Result.Reason` 코드로 보존 |
| `node demote NODE --expected-revision N --request-id ID` | 설치된 voter의 suffrage만 변경 | 현재 system-admin·entry revision/root CAS·quorum, dispatch 직전 현재 권한 재검사 | 원 Add/Remove A2 journal 경계에서 SDK `DemoteVoter`를 한 번 호출. 설치 신원/replication·native 자원·원 ACK 유지, active non-voter는 새 login issuer가 아님. 현재 leader는 남은 active voter로 먼저 leadership transfer. 재승격은 기존 `promote`의 원 신원/entry를 사용 |

클러스터 Vault는 `secret ... --all`로 고른다. 전역 `--tenant`는 작업 공간 Vault를 고른다. 범위 선택만으로 클러스터 Vault 권한이 생기지 않는다.

Unix cache의 유휴 기한에 따른 새 TLS 접속은 다음 요청 전 연결 수명 관리다. 원 profile/user/session·operation ID/서명·CAS를 바꾸거나 송신 뒤 Unknown 명령을 자동 재제출하지 않는다. 보존 Session의 만료 뒤 Open 거부는 미전송 오류이며 업무 결과의 취소가 아니다.
