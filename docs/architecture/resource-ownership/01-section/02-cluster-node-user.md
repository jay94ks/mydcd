# 자원 분류: 클러스터·노드·사용자

[자원 분류표](../01-section.md)의 한 부분이다.

| 자원 | 정의·관리 주체와 입력 | app.yaml에서 정의하거나 참조하는 내용 | 변경·종료 경계 |
|---|---|---|---|
| 빌드 Secret 승인·사용 참조·임시 mount/로그 matcher | tenant Vault와 현재 Deploy/ManageRegistry, 수락된 job의 원 build purpose | 앱 Secret mount 승인과 별개이며 실제 앱/Task를 만들지 않음 | job/Vault usage 원자 예약·같은 원 owner/provider 읽기, 취소/권한 회수 중에도 원 참조 보존. 실제 종료·Secret 파일 정리와 I/O join의 UseGone을 terminal 보고와 함께 확정해 반환. 값은 Raft/관리 JSON/공개 ARG에 넣지 않고 [빌드 Secret 경계](../../../reference/image-build-jobs/02-secret.md)를 따름 |
| 이미지 빌드의 CPU·메모리 예약 | tenant 정책과 수락된 원 job의 begin/terminal owner closure | 앱은 빌드 예산을 정의하거나 반환하지 않음 | live job에서 workload/imagebuild/TENANT/JOB/builder를 투영해 Task·registry와 같은 node/tenant 한도에 합산. 별도 관리 예약/Task를 만들지 않고 cancel/unknown은 보유. WorkspaceBytes 입력 수락 예산·CacheBytes 정리 목표와 native 종료를 구분한다. MVP는 디스크 쓰기 강제 상한이나 tenant별 디스크 고갈의 엄격한 격리를 보장하지 않으며 [job 명세](../../../reference/image-build-jobs/04-owner.md)를 따름 |
| 외부 registry 자격 참조 | tenant ManageRegistry의 put-external-registry/delete-external-registry, tenant 관리 명령. 공개 참조만 control/external-registries에 보관 | 이미지의 정확한 authority/repository로 선택. 이미지 신뢰와 실제 Secret 승인/Binding은 별도 | 같은 ID의 범위 고정·CAS, 삭제 흔적 보존·익명 fallback 금지, 내장 authority 충돌 거부. 인증용 보조 Secret은 원 앱 승인/Binding의 독립 grant로 예약하고 앱 파일·환경 키셋에는 합치지 않음. CA는 호출별 OCI 클라이언트, 검증한 이미지 config의 적재/cache는 기존 Engine 소유. 호스트 CA·mutable tag·별도 archive를 만들지 않음. 원 Task 종료 뒤 같은 사용 참조 반환. 앱 종료가 관리 정의/원 Secret을 삭제하지 않음. tenant 종료 전 명시 삭제. [외부 정의와 현재 공급 범위](../../../reference/external-registries.md) |
| legacy 원 source의 명시 소유권 매핑 | 현재 system-admin의 `map-legacy-resource`, tenant 관리 명령 또는 단일 관리 변경. 같은 `control/resources` checkpoint | 앱은 매핑/권한을 정의하거나 원 native key를 바꾸지 않음 | 원 Source ref/전체 SHA-256·tenant/user/node/network·Task의 사전 typed Reservation을 서명에 고정. Bridge/task의 모양상 일치만으로 채택하지 않음. 한 예약은 한 원 Task에만 연결하고 원 source snapshot/서명·현재/과거 권한을 분리해 보존. 미매핑/전역 discovery는 system admin만 조회하고 매핑 tenant의 Read는 자기 metadata만 제공. 매핑은 native Start/Gone·root 정책 활성화가 아니며 실제 journal/collector와 원 pin 정산 전 자원 반환을 허용하지 않음 |
| 매핑 legacy source의 Drain·종료와 예산 반환 | 현재 tenant cleanup 권한의 명시 관리 변경, 원 owner의 기존 Manager/A2·schema Gone 서명. 같은 Resources/source 원자 FSM | 앱 선언으로 native 종료 사실을 공급하거나 과거 매핑을 새 앱의 권한으로 사용하지 않음 | `drain-legacy-resource`는 원 nonce/native 세대·Task 예산을 유지해 Drain. `retire-legacy-resource`는 native/consumer 정산 뒤 source tombstone과 budget 반환을 함께 확정. 원 spec·관리/owner 서명·closing snapshot/floor를 보존. 관리 CIDR 반환은 별도다. 더 높은 managed Goal 세대가 같은 key를 사용할 때 역사적 매핑은 현재 허가/사용량에 적용하지 않음 |
| 과거 raw NodeSpec | system-admin의 별도 `retire-legacy-node-config`, 같은 Resources/source 원자 FSM | 앱은 원 NodeSpec을 정의·매핑·삭제하지 않음 | 정확한 Source/Digest/Node·두 CAS, 명시된 typed global quota와 원 owner의 모든 raw native source tombstone을 요구. 과거 설정/서명/floor는 Resources에 보존. node membership·신원·DB/journal·관리 자원의 수명은 변경하지 않음. 미지원 native 종류의 채택/종료 증명으로 사용하지 않음 |
| tenant 전체 삭제와 원 종료 inventory | system-admin의 begin/finish 관리 변경, 같은 access catalog·Raft FSM; 원 owner의 SFCP 서명 보고 | app.yaml·로컬 profile 삭제의 대상이 아님 | begin에서 신규 업무 차단과 원 inventory/owner 고정·불변 근거 checkpoint를 원자 확정. 기존 자원별 명시 종료/데이터 정산 후 데몬이 native journal·SDK·writer/flow/pin을 확인. 보고 누락·Unknown·retained 데이터가 있으면 Retiring 유지. finish는 서명 전체와 현재 census0를 요구하며 원 이력·다른 tenant·고정 경로 데이터를 보존. 런타임 계약 |
| 사용자 interactive exec 기록/I/O | 명시 사용자 session/intent·tenant Read/Deploy·원 Task/native owner. 해당 노드의 기존 private store, CLI는 Linux user profile별 원 기록 | app.yaml 목표/등록 자원이나 lifecycle checker 작업으로 생성하지 않음 | 원 exec ID·intent/시작 전 내구 marker와 양성 시작/실제 exit를 보존. I/O 종료는 프로세스 종료가 아님. 자동 재Attach/재실행·전체 컨테이너 kill 금지. 입력/출력 본문은 Raft/결과 DB에 저장하지 않음. [사용·상태 계약](../../../reference/container-operations.md#interactive-exec와-원-실행-조회)을 따름 |
| node shell 정책·노드별 sudo·사용자 node grant | 시스템 관리자/ManageCluster의 명시 set-node-shell-policy/node/grant, 같은 Raft `control/node-shell` checkpoint·공유 정책 CAS | app.yaml·tenant 관리 명령·컨테이너 lifecycle이 정의/수정하지 않음 | 기본 disabled/4세션/idle1800초. node inherit/on/off는 전역 기본값을 덮어씀. 현재 사용자 scope/계정/credential/issuer·grant·신선한 현재 owner readiness를 별도 확인. 회수/disable/sudo 변경은 원 signed 사용자 CloseOrigin/ClosedBy와 세션 종료를 연결하며 원 기록을 삭제하지 않음 |
| node shell OS 계정·로컬 SSH 키/host pin·sudoers·원 PTY/receipt | 현재 logical sfcd 한 개가 기존 observations DB와 원 node.state_dir/node-shell을 사용. root 준비와 기존 loopback sshd, OS 계정은 non-root sfc-shell | 앱이 host 계정/키·SSH 주소/host key·PTY 또는 원 session ID를 주입하지 않음. | node shell 세션 공개 목록 | 기존 셸 checkpoint의 현재 권한 조회 projection, State/Node/After 선택 | 앱/웹이 별도 원장이나 종료 결과를 소유하지 않음 | closed는 노드별 최근200개(ClosedAt 내림차순·동률 SessionID 오름차순), open은 제외하지 않는다. 사용자/필터와 보존 후 Total/Next를 계산한다. 목록 숨김은 원 operation 결과·서명·owner receipt·이벤트의 삭제나 저장 상한 확장을 뜻하지 않음 |
| 앱 컨테이너 로그 | app.yaml 서비스 logging, 각 서버 sfcd 로그 보관소, 사용자 `logs-clear` | 앱 소유 logger 설정 | 서버마다 자기 보관소에서 지운다. Raft 기록 없음, 컨테이너를 다시 만들지 않음. 서버가 꺼져 있으면 그 서버의 로그는 남는다. |
| node CLI 보안 정책 | system-admin/ManageCluster의 `set-node-cli-policy`, 같은 access catalog·Raft FSM. 별도 `manage node-cli-policy` 조회 | app.yaml이나 tenant 관리 명령에서 정의하지 않음 | 기본 false. 정책 Revision/CAS와 on/off 독립 사용자 승인 필수. true의 새 요청은 system-admin/자기 tenant-manager 및 등록 사용자 키만 허용. 등록 node key 배제·마지막 독립 관리자 키 보호. 원 Task/Binding·grant/Volume·내부 보고/정산 보존, node/DB/복제 키 수명을 바꾸지 않음 |
