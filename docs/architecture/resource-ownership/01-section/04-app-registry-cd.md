[자원 분류표](../01-section.md)의 한 부분이다.

| 앱 묶음·서비스·컨테이너·앱 설정 | app.yaml, 해당 tenant의 이름 있는 앱 inventory | 이미지 digest·argv·환경/설정·노드 배치·자원·의존·준비 조건 | 같은 앱 실행기로 생성/갱신/종료. 신규 CLI 생성은 expected=0과 이름별 부재 지문, 기존 plain 앱 갱신은 원 BeginTarget으로 수락하며 현재 권한/자원을 재검증. 빌린 관리 자원까지 소유 범위를 확대하지 않음 |

| lifecycle 검사 실행·결과/컨테이너 정책 | app/service의 고정 script·현재 Task·검사 코어와 workload/Docker SDK | 앱은 검사 방식·일정·결과별 시작/종료/재시작 정책을 선언. 스크립트는 접속 검사와 부가 동작을 수행 | 원 Task/Program·scope/check/phase별 일정과 prepared/dispatched/결과·컨테이너 제어 receipt는 node의 기존 observations DB 같은 row에 저장. 제어는 원 native/StartedAt에 고정하고 Volume 추가 Start도 기존 permit/Starting과 원 consumer를 사용. completed 시작 receipt는 같은 row의 Previous와 공유 owner 서명 관측에 보존하며 원 정책 재시작만 old exit→새 실행으로 전환. 원 read consumer만 정리하며 불명 run을 재실행하지 않음. file 내용은 같은 원 Task/native의 제한된 stat/copy 해시 비교로 소비하며 host 추출/원문 결과를 만들지 않음. 앱 scope는 원 coordinator·선언된 서비스 Target 집합에 고정하고 서비스 Healthy와 분리된 owner 서명 AppChecks로 공유 건강/완료에 게시. 다른 owner의 native I/O를 로컬 journal로 수행하지 않음.
