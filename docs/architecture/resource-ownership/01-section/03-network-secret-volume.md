# 자원 분류: 망·Secret·Volume

[자원 분류표](../01-section.md)의 한 부분이다.

| 자원 | 정의·관리 주체와 입력 | app.yaml에서 정의하거나 참조하는 내용 | 변경·종료 경계 |
|---|---|---|---|
| 이름 있는 MYDCP TUN 가상 망 | tenant 관리자, 관리 명령 | 기존 망의 이름과 서비스 attachment | 논리 망 계약의 단일 카탈로그 내 노드별 구성. TUN 망 자체와 참여 노드·소유 구성을 앱에서 생성/변경/삭제하지 않음 |
| network CIDR·node-local pool·gateway·owner·MTU·경로·Bridge/TUN native 자원 | 클러스터의 network 관리 영역, tenant 범위 관리 입력 | 이름으로 해석한 망의 주소/연결 요청과 원 자원 참조 | CIDR은 클러스터 전역 중복/겹침 거부. 새 관리 망의 GatewayMode는 확정 metadata/native spec에 보존하며 legacy 부재는 유지하고 명시 drain/fence/새 세대로만 전환. `control/network-sources`는 같은 관리 자원의 확정 metadata이며 별도 native owner가 아님. Task/Ingress는 같은 frozen source reader를 사용하고 실제 사용 허가/read-back은 원 owner가 담당. 앱 종료는 attachment/pin만 반환하며 관리 망은 유지. ledger window는 같은 완전 projection의 정확한 관리 source key만 인정하고 CIDR/native 수명·원 참조를 반환하지 않음 |
| node의 tenant/CIDR 기본 차단 table | mydcd network owner가 같은 Resources/Apps projection·미정산 native Bridge journal에서 파생. 관리 자원의 별도 사용자 입력이 아님 | 앱은 임의 firewall/예외를 작성하지 않으며 승인된 route만 사용 | 새 managed gateway의 자기 source/destination pool·정확한 Bridge/TUN interface와 승인 route를 검사하고 unknown 외부/foreign CIDR·gateway/DNS를 기본 차단. ESTABLISHED+REPLY와 같은 Bridge의 유한 IPv6 ND를 구분. 예외는 원 route TUN·방향/port에 한정. 기존 observations DB의 boot별 A2 intent와 exact own nft read-back/원자 교체를 사용하고 옛 native가 실제 종료될 때까지 보호. foreign table/규칙·Docker 전역 정책은 유지. 해당 MyDC 망만 SDK nat-unprotected/masquerade=false를 사용하고 같은 boot의 원 기본 차단 확인 뒤 최초 create. SDK record 부재만으로 기존 커널 장치를 채택하지 않으며 정확한 device의 사전 부재 조회가 거부/불명이면 SDK create 미전송으로 정산 |
| pool의 CIDR·선택 IPAM Dynamic | tenant network 관리자가 기존 Pools[]/IPAM으로 생성·명시 network change. 같은 Book과 원 Bridge spec에 고정 | 앱은 이름 참조와 허용된 static IP만 요청 | 실제 주소 설정/자동 할당은 Docker IPAM. 원 CIDR·owner·gateway/MTU·IPRange를 SDK create/inspect로 대조하고 기존 Bridge를 암묵적으로 재생성하지 않음 |
| network 변경 후보·원 변경 ID/세대 | tenant ManageNetwork의 plan-network-change와 동일 Resources CAS/Networks. 후보도 기존 global/tenant quota와 CIDR을 예약 | 앱은 후보를 직접 생성/수정하거나 원 source 대신 참조하지 않음 | 예약 중 새 논리 망 입장을 닫되 원 catalog/source에 고정한 앱·이관·DNS 참조와 pin을 보존. 새 MetadataOnly reserved 취소는 현재 cleanup scope·원 change CAS로 수행하고 native proof를 입력하지 않음. flag 없는 이전 native 후보의 취소는 target owner의 정확한 Fenced/Gone/NoPending 서명을 계속 요구. Drain 뒤 취소는 거부. native 준비·전체 member 종료·새 세대 commit과 metadata 예약을 구분 |
| DNS zone·resolver/forward/cache·서버 운영 한도 | tenant 관리 명령의 configure-network-dns와 원 공유 source | 앱은 승인된 망/alias와 resolver를 참조 | 담당 mydcd가 gateway:53 UDP/TCP를 제공. DNS query/TTL·원 socket/Bridge pin은 기존 coordinator에서 정산. client 출처는 Book의 원 세대·실행 native/설정/mount 메타데이터·Bridge endpoint로 확인하고 데이터 Volume 가용성은 Volume owner가 검사. DHCP 서버는 제공하지 않음 |
| cross-tenant route·접근 정책 | source tenant의 propose-route와 각 tenant의 명시 approve-route/withdraw-route. 같은 Resources/Networks CAS·이름 기반 원 Binding | 허가된 경로를 통한 서비스 통신. 앱 선언이 상대 tenant에 승인하지 않음 | 제안은 자기 승인이 아니며 관리자도 양측 승인2회 필요. 원 owner가 기존 TUN/nft의 RoutePolicy로 CIDR/side/protocol/port를 적용하며 packet plane은 양측 원 pin gate를 요구. 앱이 native 정책/gate를 작성하지 않음. 철회는 원 정책/flow/주소 참조를 native 종료 전 삭제하지 않음. 종료의 Authority 검증은 완전 projection으로 하되 관리 저장은 base 카탈로그의 원 RouteClosure만 변경하며 앱 Task 예약을 관리 Quota로 복사하지 않음. 정책 Active·필터 설치와 실제 native/통신 Ready 구분. IPv4 원 mark와 소유 route TUN의 src_valid_mark=1을 native 적용/read-back에 포함하고 전역 설정은 바꾸지 않음. TUN 삭제로 인터페이스 전용 설정을 회수 |
| route instance 참조·원 native Bridge dependency | 최종 승인과 같은 Authority/Resources/Apps FSM 변경. 각 consumer lifetime에 원 source key/generation/revision/spec hash 고정 | 앱은 참조/원 native dependency를 생성하거나 변경하지 않음 | 양측 참조를 원자 예약하고 Bridge borrow/route packet owner를 기존 node/global·tenant consumer 합산에 포함. withdraw/권한 회수는 원 Closed 이전 참조/예산 반환이 아님. owner의 route-work는 준비/정리 조회이며 native dispatch·Started·Ready가 아님 |
| route 원 dispatch·로컬 native record·Bridge pin | local owner가 observations DB에 원 RouteRuntime/nonce/서명 제출·Bridge lease·NativeStarted/첫 실행 NativeBoot를 sync하고 같은 Authority에 ModuleReport로 표식 고정 | 앱은 생성·수정·초기화하지 않음 | nonce는 local private DB, digest/원 boot·작업/spec은 원 shared 참조에 보존. route dispatch 보고는 전역 Apps root 동등성 대신 현재 동일 ref/lifetime·dispatch와 양측 권한을 검증한다. legacy strict root·epoch/actor floor·원 nonce/unknown은 보존하며 앱이 이 Target으로 권한을 만들지 않는다. 표식 뒤 local record 유실은 새 journal 생성 거부. 보고서의 epoch/root 봉투와 영구 dispatch/종료 사실을 구분하며 명시 window 폐쇄 후의 재게시는 같은 원 사실과 최신 quorum 조회를 요구. 준비 Dispatch.Boot와 실행 NativeBoot를 구분하고 원 실행 boot는 변경하지 않음. legacy 부재를 현재 boot로 채우지 않으며 boot가 다르거나 불명이면 새 커널의 동일 이름 자원을 원 작업으로 Recover/Remove/Quiesce하지 않음. 알려진 원 실행 boot와 현재 kernel 차이·내구 fence/reader join·readonly native/conntrack 완전 부재가 함께 입증된 이전 커널 종료는 원 ClosePackets/A2 retirement로 정산하며 새 자원을 건드리지 않음. 원 영구 종료 사실은 보존. 원 pin과 NativeStarted 뒤 같은 native만 Recover하며, 철회는 원 A2 Remove/Retiring·실제 Gone·pending0/flow0 뒤 pin 반환. daemon 종료로 persistent native/참조를 삭제하지 않음 |
| route flow pin·상대 저장 영수증·반환 token 구간 | 각 native owner의 기존 RouteRuntime checkpoint/observations DB. 상대 서명은 원 consumer/lifetime·양측 boot·tuple/주소 세대·pin에 고정 | 앱은 pin이나 저장 증거를 생성/치환하지 않음 | source 저장→destination 원 pin/상대 영수증 원자 저장→source 확인 저장 뒤 packet 입장. 재전송은 같은 pin, 정산한 상대 token은 병합 구간으로 보존해 늦은 claim을 거부. DB 불명/boot 변경으로 초기화하지 않음. source의 실제 conntrack 관측 Tracked와 단조로운 Closing은 같은 checkpoint에 보존. 조회 오류/관측 전 부재로 반환하지 않고 다른 flow는 유지. flow 영수증은 양측 실제 종료 증거가 아님 |
| 개별 flow의 peer 종료/tombstone | 각 원 owner가 같은 observations DB의 Closing·IO barrier/native drain 또는 원 pin 미입장 봉인 뒤 `route-flow-observe` Close로 영구 서명. source는 자기 정산과 peer 사실을 함께 검증해 원 pin 반환 | 앱은 claim/종료 사실·반환 token을 만들거나 다른 pin의 같은 tuple을 정리하지 않음 | 원 claim/ref/pin/boot에 고정한 같은 bytes/서명으로 응답 유실·재부팅 재개. 현재 boot/시각으로 사실을 치환하지 않음. partial/Unknown·missing journal·legacy 불명은 유지하고 원 instance/shared policy 반환과 구분. 전체 PacketClose의 영구 fence는 늦은 claim 전체를 닫음 |
| route packet의 flow 식별자 | 양측 내구 pin·ReferenceNeed·boot·tuple/클러스터에서 같은 제품 core가 source→destination 순서의16바이트 token을 도출. MYDCP Packet kind2와 동일 node relay가 전달 | 앱은 token/원 pin·목적 endpoint를 지정하거나 일반 kind1으로 우회하지 않음 | 같은 주소/port 재사용 후 옛 frame/대기열을 새 flow에 채택하지 않음. 현재 gate가 token과 Book의 실제 목적 endpoint를 대조. 별도 권위/해시체인·추가 pin이 아니며 일반 TUN kind1/PMTU 예산 유지 local 입장 후보는 원 PacketPlane이 한 개만 소유하고 기존 byte 예산을 사용한다. 미허용 추가 후보는 drop하며 Stop은 worker/callback join과 bytes 반환을 확인한다. 후보는 새 native pin이나 별도 내구 작업이 아니다 |
| 철회 instance의 로컬 packet 종료 receipt | 원 owner가 core fence sync·reader/callback/write/큐 join·같은 native의 fenced 모드/소유 conntrack 빈 census 뒤 기존 RouteRuntime에 서명 저장 | 앱이 종료 사실을 제출하거나 peer 종료를 대신하지 않음 | 원 flow 집합 digest/count와 A3 반환을 같은 checkpoint로 고정. native Gone/Bridge 반환과 별도 단계이며 상대 shared 참조는 상대 종료까지 유지. 재개/새 boot가 원 digest를 빈 값으로 바꾸지 않음 |
| route native table·RPDB/conntrack 선택 | 원 Bridge device/정책 namespace·native spec에서 파생, 같은 TunnelDriver의 원 Apply/Recover/Remove | 앱은 mark/table/device를 직접 지정하거나 덮지 않음 | 원 Bridge iif/prefix/mark에 한정. 기본 unreachable guard로 부분 적용의 main fallthrough 방지. foreign 자원은 보존하고 nft/RPDB/default guard 종료까지 Gone을 주장하지 않음. kernel 경로 선택과 양측 flow 입장/정산을 구분 |
| route instance·policy의 영구 종료 receipt | 원 owner가 native/Bridge/flow 정산 뒤 두 서명과 제출을 같은 local record에 저장하고 route-retirement로 보고. | 권한 회수·미준비 route 정산 | Catalog 변경의 같은 FSM에서 무효한 Active route를 Revoking으로 전환. 원 owner는 확정된 Revoking·immutable grant 부재 아래서만 NeverDispatched 종료 보고 | 앱은 grant 부재/로컬 기록 부재를 근거로 직접 자원을 반환하지 않음 | Catalog/Resources 원자 변경, 참조/원 승인 보존. private proposal/nonce/불명 제출을 재작성하지 않고 실제 grant 뒤 missing journal은 초기화 거부. session logout/권한 복구로 persistent route를 임의 철회/재활성화하지 않음 |
| Secret Vault·다단 Secret Group·Secret 공개 metadata·ACL/보호 정책 | tenant 관리자, 관리 명령. 설치 공급자 자격은 보호된 별도 설정 | 기존 Group/Secret의 명시 순서·고정 공급 참조·[파일/환경 변수 projection](../../../reference/secret-delivery.md) | 앱 down/prune가 Vault/Group/Secret을 삭제하거나 ACL을 변경하지 않음 |
