### Legacy 원 source의 명시 매핑

과거 raw NodeSpec의 회수는 같은 User submit/result/resume의 별도 `retire-legacy-node-config` 관리 명령이다. Source(Key/Generation/Revision), 전체 SHA-256 Digest, 역사적 Node 이름과 source revision Expected·Resources root CAS를 고정한다. 현재 system-admin과 기존 typed global quota, 같은 owner의 모든 raw native source tombstone이 필요하다. 원 NodeSpec/서명/floor는 같은 Resources에 보존하고 node membership·신원·native journal을 바꾸지 않는다. tenant 관리 명령이나 앱 CD에 포함하지 않으며 native 종료 사실을 생성하지 않는다.

`map-legacy-resource`는 기존 User submit/result/resume의 signed UserOperation과 Resources root CAS를 사용한다. Change.Expected는0이고 payload는 Source(Key/Generation/Revision)·전체 SHA-256 Digest·Tenant/Node/User/Network, Task에는 사전 typed Reservation key도 포함한다. 현재 system-admin이 결정하고 target user의 현재 tenant/node ManageNetwork 또는 Deploy·image trust를 별도로 확인한다. Bridge 매핑 뒤 Task를 연결하며 한 예약의 중복 source 사용을 거부한다. 원 spec/key/label/journal/pin과 계정 역할은 변경하지 않는다. 원 snapshot/최초 서명은 같은 Resources checkpoint에 보존하며 metadata 수락은 설치 root 정책 전환이나 native Start/Gone이 아니다.

`drain-legacy-resource`는 Tenant/현재 Source/고정 nonzero16바이트 Nonce와 source revision expected를 사용한다. 기존 Resources root CAS로 native spec/key/세대를 바꾸지 않고 원 Lifecycle만 Drain하며 Task 예산도 같은 FSM에서 Drain한다. `manage apply`로 보낼 수 있다. `retire-legacy-resource`는 Tenant/현재 Source/owner Proof와 Task의 선택 Budget ReservationClosure를 받는 별도 명시 관리 작업이다. 실제 원 native Manager.Gone·Pending/pin0 관측 뒤만 owner가 기존 schema.GoneBytes로 서명하고, reducer는 현재 cleanup 권한·source CAS·서명과 별도 예산 ID/세대를 확인한다. 원 source tombstone/예산 반환을 원자 확정하며 원/closing snapshot·최초 관리 서명·종료 사실/floor는 같은 checkpoint에 보존한다. generic user/raw native patch는 허가하지 않으며 기존 bound related-control-patches-1의 정확한 source key만 허용한다. 아직 선언된 raw Task가 있으면 Bridge 종료 정산을 거부한다.

기존 Member/Read `observe`는 mapped local source에 대해 compact native journal/상태와 선택 typed Retirement를 반환한다. Retirement에는 위 Source/owner Proof/선택 Budget만 있고 원 spec/user Session은 없다. 이는 public user의 임의 원격 source/closure 공급이 아니다. 같은 app-native-permit는 매핑 source의 현재 Work/target user grant·trust/예산을 검사하고 원 spec hash와 Bridge ConsumerBudget을 반환하며 actual native 존재/종료를 주장하지 않는다. legacy private registry source에 app Binding/TaskSubject 권한을 합성하지 않는다. 역사적 mapping은 원 세대에 한정하며 더 높은 managed Goal의 새 permit/종료는 기존 앱 계약을 따른다.

resources는 선택 tenant에 명시 매핑된 Legacy(Source/Digest/Kind/Mapping)를 반환하고, 미매핑/전역 목록은 Tenant 생략의 system-admin 조회만 제공한다. 원 source 바이트/관리자 Session·서명은 반환하지 않는다. 기존 한 페이지8개·After cursor·ResourcesViewIndex와 schema1을 유지하며 CLI의 명시 `--system`이 이 조회를 선택한다. 미지원 raw source 종류는 discovery로만 보여 주고 자동 native 채택/호환 성공을 만들지 않는다.

User method `legacy-resource-closure`는 Tenant와 선택 LegacySource(ObjectRef)를 요구하며 다른 method의 LegacySource/After/Node 혼합을 거부한다. 기존 User kind1/relay kind3·schema1·current session/challenge 서명 경계를 사용하고 Bridge ManageNetwork/Task Deploy cleanup scope를 검사한다. 최신 quorum의 원 Drain/source/예산을 해석한 뒤 같은 daemon의 local 또는 authenticated Member observe로 원 owner의 사실만 읽는다. IO 뒤 source/예산과 현재 role/session·입구/relay를 재검사하고 변경/회수·불명/위조 사실은 성공으로 내보내지 않는다.

응답의 선택 LegacyTarget은 Tenant/Node/Kind/Owner/Source·RetirementDigest·선택 typed Budget, LegacyRetirement는 원 Tenant/Source/owner Proof/선택 ReservationClosure다. ResourcesViewIndex/ResourcesRootRevision·Catalog RootRevision·ModuleEpoch를 같은 최종 view에서 제공한다. 원 native spec/Secret/Session은 반환하지 않는다. RetirementDigest는 기존 native proof-input SHA-256이며 schema.GoneDigestBytes는 기존 GoneBytes의 서명 domain/bytes를 유지한다. CLI는 이 digest와 owner public key로 사실을 검증하며 권한은 TLS pin/current quorum의 정책에서 얻는다. 사실 검증이 사용자/Member 권한·정산 성공을 부여하지 않는다. 이 조회는 readonly이며 command/새 ID를 만들지 않고, 별도 retire-legacy-resource가 현재 권한/두 CAS로 정산한다. wire/ABI 번호는1을 유지한다.
