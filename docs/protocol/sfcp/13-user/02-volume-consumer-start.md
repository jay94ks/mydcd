### Volume consumer와 최신 Start 허가

`create-volume/acquire-volume/release-volume` UserOperation은 `control/volumes` root CAS를 사용한다. whoami의 `Data.Roots["control/volumes"]`로 Prepare가 원 CAS를 고정하며 별도 서명/합의 프로토콜을 만들지 않는다. Change.Expected는 생성0, consumer 획득/반환은 해당 Volume State.Revision이다. 생성 payload는 노드 서명의 NativeReady이며 native spec/scope·physical generation·원 owner를 결합한다. host path/private key는 포함하지 않는다. 획득은 현재 session의 ManageVolumes·원 owner node 할당, 반환은 현재 cleanup 권한과 원 owner 서명의 Gone을 요구한다. consumer의 원 principal을 변경하거나 단일 writer 규칙을 우회하지 않는다.

User method `volumes`는 Tenant별 Read, Tenant 생략 시 ManageCluster를 요구한다. typed `Data`로 최대8개의 VolumeView(`Items`)와 `Next`/`RootRevision`(Volumes root)/`Revision`(volumes book)/`ModuleEpoch`를 반환하며 cursor는 최대512바이트다. 내구 consumer/종료 증거는 실제 Volume owner가 생산하며 논리/native 삭제는 명시 `volume delete`와 원 결과/재개 경로를 사용한다.

노드의 `volume-permit`는 기존 Management kind16(read)의 서명 request를 사용하며 Latest=true·Key 생략·현재 Member/Read를 요구한다. 현재 control이 Raft barrier 뒤 caller의 전체 키와 실제 Volume owner/node/key·원 consumer·현재 principal/tenant/node 권한을 검사한다. consumer grant는 확정된 배포 의도이며 요청마다 새 로그인 session을 발급하지 않는다. 앱의 별도 Binding/Secret 승인 검사는 이 허가만으로 생략할 수 없다. 허가는 Scope/Consumer/Boot/Challenge/Sequence에 결합된 기존 Permit이며 응답은 Local=false와 실제 RaftIndex를 가져야 한다. 단절/부재/거부 때 local Shared나 cached 허가로 대체하지 않는다. member1회 relay는 원 signed caller를 보존하며 연결 최초 Member flag 대신 현재 정책을 검사한다.

부분6시험은 실제 user/SFCP/Raft/bbolt·동적 N3/Q2 단절/복구·Snapshot/같은 DB와 별도 실제 native 준비 서명을 확인했다. runtime의 native fact는 서명 fixture이며 local Gate 소비는 메모리다. 실제 내구 Gate/Start/Fence·원 Unknown 정산·named mount와 종료 증거는 아직 연결 전이다. 기존 Management 목적/프레임 형식과 schema1을 유지한다.

control/resources를 선택하는 action은 map-legacy-resource/drain-legacy-resource/retire-legacy-resource/set-node-quota/reserve-task/drain-reservation/release-reservation/create-tun-network/configure-network-dns/plan-network-change/cancel-network-change/fence-network-change/commit-network-change/reconfigure-tun-network/propose-route/approve-route/withdraw-route/create-virtual-bridge/approve-virtual-bridge/close-virtual-bridge/drain-network/leave-tun-network/join-tun-network/set-network-toggle다. 가상 브릿지 거절은 고유 결과 사유를 가진다: 22 `bridge-exists`, 23 `peer-closed`, 24 `network-changing`, 25 `bridge-attached`(마지막 member leave와 빈 reconfigure도). node는 같은 root에 `virtual-bridge-closed` ModuleReport(Kind `virtual-bridge-closed`, 노드 서명 BridgeClosure)를 보낸다. UserOperation의 원 서명/actor/epoch/request ID와 root CAS를 유지한다. set-node-quota는 현재 ManageCluster, 예약/망 변경은 해당 tenant/action/node, 원 정산은 같은 현재 session의 cleanup scope를 검사한다. owner는 현재 installed member에서 결정하며 self-asserted key로 바꾸지 않는다.

최종 route 승인은 같은 FSM에서 정책과 Authority의 양측 instance/원 Bridge dependency를 예약한다. `route-work`는 기존 Management의 authenticated Member·Latest=true·비-local quorum 읽기로 자기 owner의 Reference/peer·불변 Tunnel 정책과 PrepareAllowed만 제공한다. 입력은 Reference(원 consumer ID), At(서버 현재30초 이내)이며 원 user/API가 native dependency를 직접 제출하지 않는다. 준비 조회를 native effect 허가나 실제 Ready로 표시하지 않으며 권한 회수 뒤에도 원 cleanup 정의/참조를 보존한다. policy/참조/실제 source/flow generation은 서로 다른 좌표다.

`route-dispatch`는 같은 Management의 Member 쓰기다. schema1/Kind=route-dispatch·Cluster·Reporter·Epoch·RootRevision·Dispatch·Signature를 받는다. Dispatch는 Cluster·원 ReferenceNeed·Boot·Journal digest·Spec(policy hash)·NativeSpec(동일 코어에서 파생한 TUN hash)·Operation=1·원 owner Signature다. 바깥 서명 prefix는 `sfc-route-dispatch-report-1\0`, 안쪽은 `sfc-route-dispatch-1\0`이며 Signature를 비운 JSON을 서명한다. 기존 ModuleReport의 원 content RequestID/root CAS/epoch와 같은 Apps/Authority 저장을 사용한다. CAS 재제출에서 안쪽 원 신원을 바꾸지 않으며 중복은 원 결과 또는 같은 표식으로 정산한다.

`route-native-permit`는 Member·Latest=true·비-local 읽기다. Reference·Nonce(원 private DB 값)·Operation=1·At(서버 현재30초 이내)를 받고 schema1·ReferenceNeed·Journal·NativeSpec·Operation을 반환한다. 현재 route-work의 PrepareAllowed와 같은 원 nonce digest/표식을 요구한다. Nonce를 공유 projection/응답/로그에 남기지 않는다. 허가는 첫 Apply의 현재 입장 조건이며 실제 실행/Ready/Gone·양측 flow pin을 증명하지 않는다. 별도 Raft/RPC/DB 경로를 추가하지 않는다.

`route-retirement`는 같은 Member·Latest=true·비-local Management 쓰기다. schema1/Kind=route-retirement·Cluster·Reporter·Epoch·RootRevision(Apps)·ResourcesRevision·원 Dispatch·Close(ReferenceClose)·Route(RouteClosure)·Signature를 받는다. Signature를 비운 JSON에 `sfc-route-retirement-report-1\0` prefix로 서명한다. 원 dispatch와 양쪽 종료 proof의 owner/consumer/lifetime/정책 세대/side·실제 NativeGone/미정산0을 검증하고 기존 ModuleReport content RequestID와 원자 Apps/Resources checkpoint를 사용한다. unrelated root/native source patch는 허용하지 않는다. Close.At는 원 영구 종료 시점이며 읽기 permit의30초 한도로 폐기하지 않는다. CAS 재시도는 명시 거부 뒤 같은 inner proofs와 현재 바깥 root/epoch를 사용하며 같은 epoch의 불명 응답에서는 정확한 원 제출을 유지한다. 명시 window가 더 높은 epoch로 닫힌 경우에는 latest route-work/동일 로컬 snapshot의 원 영구 dispatch/paired closure를 먼저 대조한다. 해당 원 참조의 사실 부재와 옛 epoch fence를 함께 입증한 경우에만 같은 inner proofs로 바깥 봉투를 갱신한다. receipt 부재/Expired만으로 원 작업 미실행이나 새 native 실행을 주장하지 않는다. policy 삭제 뒤에도 consumer의 선택 RouteClosed와 Closed/Dispatch를 보존하여 동일 보고와 ACK 유실을 판별한다. 선택 NeverDispatched=true는 zero Dispatch와 확정된 Revoking/원 consumer의 grant 부재를 요구한다. 이 grant는 native permit/Bridge borrow에 선행하는 immutable 권한 기록이므로 로컬 관측 부재와 구분한다. 실제 grant가 있으면 이 모드로 종료하지 못한다. route-work의 선택 Retiring은 같은 원 policy 세대가 Revoking인지 알리며 native 입장 허가를 대신하지 않는다.

`route-flow-observe`는 authenticated Member인 자기/원 반대편 owner가 해당 native owner에 보내는 Management Latest=false 요청이다. leader로 flow 작업을 전달하지 않는다. 요청은 schema1·Reference·선택 Tuple/Receipt/Native이며 Tuple 부재는 원 native proof 조회, Tuple만 있으면 원 pin 영수증 조회, Receipt를 함께 보내면 그 원 pin에 상대 영수증을 결합한다. Native+Tuple+Receipt는 destination에 source의 이미 저장된 claim으로 입장을 요청하며 destination pin/상대 영수증을 한 후보로 sync한다. 수신 owner가 latest route-work와 같은 로컬 committed epoch/Apps/Resources·원 Bridge/TUN read-back·현재 permit을 확인한다. source pin/native/DB를 재생성하거나 불명 응답 뒤 다른 pin을 발급하지 않는다. 응답은 schema1·Native·선택 Flow/PacketReady다. PacketReady는 실제 serving plane/context와 현재 signed path/MTU plan의 관측이며 flow 입장·quorum·Docker 통과·서비스 Ready가 아니다. fixture는 양측 원 native proof와 이 IO/path 관측을 함께 대조하고 단발 UDP를 보낸다. 이 요청은 IP packet을 운반하지 않는다.

Close+Tuple mode는 Receipt/Native와 혼용하지 않는다. 선택 CloseQuery=true는 같은 인증·원 ref/claim 아래 이미 저장한 tombstone만 read-back/서명한다. pin 반환·봉인·gate/native 변경을 수행하지 않고, 종료 사실이 아직 없으면 오류를 반환한다. 검증 조회가 cleanup을 대신하지 않도록 이 모드와 실제 Close 실행을 구분한다. source는 원 Closing checkpoint의 claim을 서명하여 보내고 destination은 현재 authenticated Member인 원 source owner·공유 원 consumer/lifetime·양측 ref/원 boot/pin/tuple·서명을 검사한다. 이 mode는 local committed 원 참조를 쓰는 cleanup이며 새 입장 quorum/Ready/native 효과를 허가하지 않는다. 원 destination pin이 있으면 Closing sync·현재 gate 게시·실제 IO barrier/native exact drain 뒤 원 pin 반환과 source token tombstone을 한 checkpoint로 저장한다. 아직 입장하지 않은 원 claim은 같은 original DB의 부재를 대조한 뒤 source token을 먼저 봉인한다. missing owner journal/legacy 불명 pin을 미입장으로 바꾸거나 다른 pin의 같은 tuple을 정리하지 않는다.

응답의 선택 Closed는 RoutePeerFlowClose다. Cluster·destination ReferenceNeed·Boot·원 Claim·JournalSynced/Stopped/NoPending/Tombstoned·Signature를 가지며 Signature를 비운 JSON에 `sfc-route-peer-flow-close-1\0`를 붙여 서명한다. Boot는 Claim.PeerBoot인 원 destination boot로 고정한다. 현재 프로세스의 boot/시각을 새 영구 사실로 넣지 않아 같은 tombstone은 같은 bytes/서명으로 재구성된다. 실제 DB read-back 뒤에만 flags를 서명한다. source는 자기 원 Closing/현재 IO barrier/native drain과 이 영구 peer 사실을 함께 검증한 뒤 원 pin을 반환한다. peer IO는 routeMu 밖이며 바깥 대기/응답 유실은 원 Closing·claim/pin을 보존한다. 영구 instance PacketClose가 있으면 그 전체 fence가 늦은 claim의 개별 tombstone을 포함하며 원 bulk receipt를 변경하지 않는다. 이 응답은 shared policy/native Gone·다른 owner의 instance 반환이 아니다.

Flow 영수증은 Cluster·ReferenceNeed·Boot·Pin·Tuple digest·Peer ReferenceNeed·PeerBoot·PeerPin·JournalSynced·Signature다. Signature를 비운 JSON에 `sfc-route-flow-receipt-1\0`를 붙여 서명한다. source의 PeerPin은 zero, destination의 PeerPin은 원 source pin이다. source pin 저장→destination의 원 pin/상대 영수증 원자 저장→source의 응답 결합 저장 후 양측 packet gate를 연다. 원 owner DB read-back 뒤에만 JournalSynced/서명을 게시한다. 동일 응답 유실은 원 pin/영수증으로 재개하고 다른 pin/boot/lifetime/tuple 치환을 거부한다. 반환된 상대 token은 원 checkpoint의 병합 구간으로 보존해 늦은 claim을 거부한다. boot 변경 후 과거 증거는 정산용으로 보존하지만 새 boot의 packet 허가로 사용하지 않는다. peer pin 영수증은 실제 전송·양측 종료 증명이 아니다.

route Packet은 같은 PathControl/Packet DATAGRAM을 사용한다. scope는 기존 tunnelScope schema1에 route NetworkID와 양측 원 consumer ID·정책 hash·source revision/instance generation을 같은 owner 순서로 고정한다. 실제 underlay route·서명 path/MTU를 확인하고 packet의 원 endpoint incarnation·방향/port·양측 저장 gate를 다시 검사한다. local TUN reader만 Admit에서 제어 I/O를 하고 수신 handler는 readonly gate/bounded queue로 처리한다. 같은 node의 두 tenant는 QUIC self-path를 만들지 않고 명시 LocalRoute/ReceiveLocal에서 같은 원 endpoint/gate/큐 재검사를 수행한다. 일반 packet 정책은 계속 local 목적지를 거부한다.

일반 TUN은 Packet kind1의 endpoint16을 유지한다. route는 schema1 Packet kind2의 tag3에 양측 저장한 flow token16을 사용한다. `sfc-route-packet-1\0` 뒤 Cluster·Source/Destination ReferenceNeed·SourceBoot/DestinationBoot·SourcePin/DestinationPin·Tuple hash를 이 순서의 정규 JSON으로 붙여 SHA-256의 앞16바이트를 취한다. source→destination 순서는 정책 방향이며 reply에서도 바꾸지 않는다. 이 값은 별도 권위/합의가 아니라 원 양측 pin의 packet 식별자다. 수신과 queued write는 현재 core의 token을 대조하고 같은 Book에서 도출한 실제 목적 endpoint를 기존 PacketPolicy로 검사한다. 같은 주소/port가 재사용되어도 옛 token을 새 flow로 채택하지 않는다. route의 kind1·일반 TUN의 kind2는 거부한다. owner32/network16/token16/IP의 네 TLV를 유지하여 overhead120바이트와 PMTU 예산을 바꾸지 않으며, 동일 node relay도 같은 token을 전달한다.

철회 instance의 로컬 PacketClose는 원 RouteRuntime checkpoint에만 저장하는 영구 사실이다. Cluster·ReferenceNeed·Boot·Native·Spec·정산 전 Flows/FlowDigest·JournalSynced·ReadersStopped/QueueEmpty/AdmissionsStopped/ConntrackEmpty·Signature를 가지며 Signature를 비운 JSON에 `sfc-route-packet-close-1\0`를 붙여 서명한다. core fence sync·실제 reader join·원 native fenced mode/conntrack 빈 census 뒤 A3 로컬 반환과 함께 sync한다. 재개는 동일 서명/원 digest를 유지한다. 새 SFCP message/합의 로그는 추가하지 않으며 이 사실을 peer 종료나 shared retirement/Gone으로 전송하지 않는다. 최종 원 shared 종료는 기존 route-retirement 두 proof로 정산한다.

plan-network-change의 새 예약은 공유 Networks에 MetadataOnly를 저장한다. 후보는 native source/허가를 갖지 않고 resources 조회의 Native는 빈 값이다. cancel-network-change는 같은 reserved generation/revision CAS·현재 ManageNetwork cleanup 권한으로만 취소하며 Candidate는 생략/빈 값이다. metadata 예약에 대한 native 증거 입력과 Drain 뒤 취소는 거부한다. 이전 flag 부재/false의 native 후보는 정확한 원 owner 서명을 계속 요구하며 관측 부재로 취소하지 않는다. metadata 취소의 관리 Applied를 원 serving network의 종료/재생성으로 해석하지 않는다.

method resources는 typed method다. `Params:{Tenant?,After?}`의 Tenant가 비면 현재 system-admin을, 지정하면 해당 tenant Read를 요구한다. After는 최대512바이트의 정렬 cursor다. 응답 `Data`는 Items 최대8개·Next/RootRevision·Revision/NetworkRevision/QuotaRevision과 view Index를 제공한다. RootRevision은 A1 root CAS, 나머지는 각 제품 코어 revision이다. 여러 page는 같은 Index여야 하며 Resources root CAS와 현재 Catalog 권한도 보존한다. 관리 원 source를 포함한 derived 목록은 Resources root만으로 동일 view를 증명하지 않는다. network 행의 선택 Change는 현재 후보 ID·Generation/Revision/TargetRevision·Phase·Target·Native ID만 제공하며 전체 종료 서명/이전 후보 이력은 복제하지 않는다. 후보 예약과 취소도 같은 submit/result/resume을 사용하고 별도 RPC/합의 로그를 만들지 않는다. whoami의 `Data.Roots["control/resources"]`로 제한된 쓰기 scope가 자원 목록을 읽지 않고 원 intent를 준비할 수 있다.

기존 observe의 관리 network source 응답은 Drain일 때 선택 Retirement에 owner 서명 NetworkClosure를 담는다. logical network generation/revision과 native source/journal의 generation/revision은 별도로 검사한다. 원 Book/참조 preflight·Bridge/TUN의 실제 Gone 뒤에만 생산하며 Ready=false인 종료 사실이다. 기존 submit/result/resume의 fence-network-change는 원 change generation/revision·Resources root CAS와 이 proof를 받아 동일 Authority의 주소/참조·Drain/owner를 다시 검사한다. 해당 member를 fenced로 확정하고 종료된 source만 tombstone으로 철회하며 다른 member의 종료나 전체 target commit을 대신하지 않는다. commit-network-change는 tenant/논리 이름·전체 member change CAS와 관리 Networks revision을 고정하고, 전부 fenced/tombstone일 때 같은 Authority archive/floor·target·새 source를 한 FSM 변경으로 게시한다. source 재생성의 generation은 기존 FSM이 부여하며 새 native Ready를 뜻하지 않는다. reconfigure-tun-network는 같은 원 member change CAS와 명시 전체 Target으로 node 구성/CIDR 담당을 교체한다. 원 change/종료 서명과 native key/generation/spec은 같은 Authority archive에 남기고 정확한 tombstone만 Closed로 재투영한다. Target.Members 누락/null은 거부하며 []의 전체 폐기는 DNS disable/원 정산을 요구한다. 새 protocol 목적·RPC·공유 로그는 추가하지 않는다.

한도 Payload의 Revision과 새 예약/망의 Generation/Revision은0으로 제출하며 Change.Expected는 기존 대상 또는 해당 코어 revision을 명시한다. 추가 물리 TCP/RPC나 새 합의 계층을 만들지 않는다. 현재 부분6시험은 공유 정책/참조 경계이며 Docker/커널 준비·제거 성공은 아니다.
