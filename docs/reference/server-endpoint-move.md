# 가입한 서버의 주소 바꾸기

집에 둔 서버는 공유기가 IP를 바꿔 주는 일이 잦다. 가입을 마친 서버의 IP나 포트가 바뀌면 빼고 다시 넣지 않고 주소만 바꾼다. 이름·키·투표 여부·컨테이너·볼륨은 그대로다.

모든 서버가 `set-node-endpoint`를 아는 빌드로 올라간 뒤에만 쓴다. 옛 빌드 서버는 이 작업을 몰라 다른 서버와 상태가 어긋난다.

가입하지 않은 서버(`invited`)는 이 절차가 아니라 `sfcli node add NODE --replace --endpoint ... --public-key ...`로 다시 등록한다.

## 절차

서버 `node-c`가 `192.168.1.103:7946`에서 `192.168.1.113:7946`으로 바뀐 예다.

```sh
# 1. 옮긴 서버에서 (sfcd는 멈춘 채로)
sudo systemctl stop sfcd
sudo sed -i 's/^\(\s*listen:\).*/\1 192.168.1.113:7946/' /etc/sfc/node.yaml   # 또는 직접 고친다
sudo sfcd --config /etc/sfc/node.yaml set-listen

# 2. 관리 PC에서 (다른 서버를 거쳐도 된다)
sfcli node set-endpoint node-c 192.168.1.113:7946

# 3. 옮긴 서버에서
sudo systemctl start sfcd

# 4. 확인: Endpoint가 새 주소이고 단계가 active(또는 ready)
sfcli node show node-c
```

1과 2는 어느 쪽을 먼저 해도 된다. 3은 1 뒤에 한다.

- `sfcd set-listen`: node.yaml의 `listen`을 이 서버의 주소로 받아들인다. 서버는 설치할 때의 주소와 다른 `listen`으로는 켜지지 않는다(설정 파일이 섞이는 것을 막는다). 이 명령은 서버 자신의 설치 기록에 새 주소를 적고 그 서버 키로 다시 서명한다. sfcd가 돌고 있으면 거절한다. 설치할 때의 주소로 되돌리면 덧적은 주소를 지운다.
- `sfcli node set-endpoint NODE HOST:PORT`: 시스템 관리자 명령이다(`set-node-endpoint`, CAS는 그 서버 항목의 revision). 클러스터 기록에 새 주소를 적고, 리더가 그 주소를 Raft 구성의 서버 주소로 바꾼다. 바뀐 구성이 실제로 설치된 것을 본 뒤에 항목의 주소가 새 주소가 된다. 그동안 단계는 `moving`이다. 명령은 그때까지 기다린다(`--no-wait`이면 받아들여진 뒤 바로 끝난다).
- 관리 PC의 context가 그 서버를 가리켰다면 context도 옮긴다. 키는 그대로라 같은 키를 새 주소에서 다시 확인한다.

```sh
sfcli context set lab-home --endpoint sfcp://192.168.1.113:7946
sfcli context trust lab-home
```

## 움직임

- 옮기는 동안 다른 서버는 옛 주소와 새 주소 둘 다 그 서버의 Raft 주소로 받아들인다. 바뀐 구성이 커밋된 뒤부터 리더는 새 주소로 연결한다.
- 서버끼리 연결은 먼저 연결한 쪽의 세션 하나를 양쪽이 함께 쓴다. 옮긴 서버가 켜지면 다른 서버에 먼저 연결하므로, 클러스터 기록이 아직 옛 주소여도 그 세션으로 복제를 받는다.
- 투표 서버가 셋 이상이면 옮기는 서버 하나 없이도 과반이 남아 구성을 바꿀 수 있다. 투표 서버가 둘이면 두 서버가 모두 켜져 있어야 바뀐 구성이 커밋된다.
- 첫 서버(genesis)도 옮길 수 있다. 클러스터 ID와 묶인 처음 주소 기록(genesis)은 그대로 두고, 그 서버의 현재 주소만 바뀐다.
- 다른 서버가 쓰는 주소나, 다른 서버가 옮겨 가는 중인 주소로는 옮기지 못한다.
- 그 서버에 가입·투표 변경·키 회전 같은 다른 멤버 변경이 진행 중이면 끝난 뒤에 한다.
- `sfcd restore`로 클러스터를 다시 세운 서버는 아직 이 명령으로 옮기지 못한다.

## 미리 막기

공유기에서 서버의 IP를 고정(DHCP 예약)해 두면 이 절차가 필요 없다.
