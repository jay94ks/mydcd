## 자동 배포 (UI-40~43)

`mydc cd`와 같은 변경을 만든다. 후보 고르기·소스 받기·계획·권한 판단은 mydcd 몫이고, 웹은 앱 행의 CD 상태를 읽어 CLI와 같은 CAS 값을 채울 뿐이다. 모든 변경은 `{op}`(작업 절)를 돌려준다.

- `GET /t/{t}/apps/{app}/cd` → `{app, deployment, health, operation, cd}`. `cd`는 `GET /t/{t}/apps`의 `cd`와 같다. CD 앱이 아니면 404 `not-cd`.
  - 상태: `revision`(모든 동작의 expected), `paused`, `running`·`candidate`(commit), `candidateDigest`(후보 승인·동기화에 쓰는 hex), `sync`·`effectiveSync`(`Paused` 포함)·`operation`·`health`·`source`(`Error`면 `sourceError`), `blocked`(`unavailable`/`current-inputs`/`current-authority`/`group-approval`), `transition`·`transitionPhase`, `lastSuccessCommit`, `activeOperation`, `changeCount`.
  - 정책: `policyRevision`, `policy`, `repository`·`branch`·`mode` 요약, `principal`(등록한 사용자 ID). 값 고정: `overrideRevision`, `overrideCount`, `overridePaths`.
- `POST /t/{t}/apps/{app}/cd/{sync|recover|replan|pause|resume|abandon}` `{opId, expected?}`. sync·recover만 `{operation?, candidate?}`를 더 받는다.
  - Expected는 행의 `cd.revision`이다. sync·recover는 행의 실행 의도 target도 싣는다(`mydc cd`의 기본). `expected`를 보내면 target 없이 그 revision으로 엄격하게 맞춘다(`--expected-revision`). 낡았으면 op가 `failed`다.
  - sync·recover는 행의 후보를 고른다. `candidate`(보던 `candidateDigest`)를 보내면 그새 후보가 바뀌었을 때 409 `candidate-changed`다. 후보가 없으면 409 `no-candidate`. `operation`은 배포 작업 ID(기본 `sync-{opId}`, 소문자·숫자·`-`, 63자 이하, 아니면 422).
  - 가짜: 일시정지 중 sync는 `failed`. 적용하면 후보가 실행 중 commit이 된다.
- `PUT /t/{t}/apps/{app}/cd/policy` `{opId, policy, expected?}` → `configure-app-cd`(PolicyRevision = 행의 `policyRevision`). `policy`는 `cd.policy`와 같은 모양이다: `{enabled, source:{kind, repository, ref, path, credential(credential_profile)}, poll(초), sync:{mode(automatic/manual), drift, prune, allowEmpty}, runtime:{mode, expiry}, limits:{fetch, bytes, queued, active}}`. 읽은 것을 고쳐 그대로 보내면 된다. 모르는 필드나 32 KiB를 넘으면 422. 허용하는 Git 출처·인증 프로필은 mydcd가 판단한다.
- 값 고정(`mydc cd override`):
  - `GET /t/{t}/apps/{app}/cd/field?path=services&path=web&path=image` → `{target, schema, tenant, app, revision, path, override?:{revision, actor, anchors}, refs}`. 고정할 수 있는 경로: `services.<서비스>.{image, command, entrypoint, user, stop_signal, stop_grace_period, cpus, mem_limit, dns, dns_search, logging}`, `services.<서비스>.environment.<KEY>`, `services.<서비스>.healthcheck.{test, interval, timeout, retries, start_period, start_interval, disable}`. 아니면 422.
  - `PUT /t/{t}/apps/{app}/cd/overrides` `{opId, path:[...], value}` → `override-app`. `value`는 그 필드의 JSON 값이다. 데몬이 필드를 다시 읽어 Expected(필드 revision)·target·기존 고정 revision을 채운다. 서비스에 고정할 배포 객체가 없으면 409 `no-ref`.
  - `DELETE /t/{t}/apps/{app}/cd/overrides` `{opId, path}` → `release-app-override`. 고정이 없으면 409 `no-override`.
- 이력·값·변경점(REQ-46 mock, 읽기 전용, 앱 Read):
  - `GET /t/{t}/apps/{app}/cd/history?after=` → `{items:[{commit, candidateDigest, plannedAt, result, reason?, operation?, finishedAt?}], next, revision, asOf}`. 최신 순. result: `candidate`/`running`/`succeeded`/`failed`/`abandoned`/`blocked`(reason = `cd.blocked`, 새 후보에 밀린 후보는 `abandoned`·`superseded`). 행마다 그 후보의 웹훅 확인 `checks?: {pre-sync?, post-sync?}`가 붙는다(`GET …/cd`의 `webhook`과 같은 모양, mydc-web이 앱마다 최근 400건 보관).
  - `GET /t/{t}/apps/{app}/cd/values?path=…` → `{tenant, app, path, running?, candidate?, gitRunning?, gitCandidate?, current?, overridden, secrets?}`. 경로는 `cd/field`와 같다(아니면 422). `git*`는 그 커밋의 Git 원문 값(없으면 빠짐), `current`는 지금 적용 값(고정 값이 있으면 그 값). 비밀값에서 오는 값은 주지 않고 `secrets`에 selector만 준다.
  - `GET /t/{t}/apps/{app}/cd/changes` → `{tenant, app, running, candidate, services:[{service, fields:[{path, before?, after?}]}], added, removed, count}`. 실행 중 커밋 → 후보. `count` = `cd.changeCount`. 비밀값은 참조만.
  - CD 앱이 아니면 mydcd가 거절한다(422).
- 묶음 승인은 배포 절의 `cd/approvals`를 쓴다.
- Git 밖 웹 서비스(mydcd의 로컬 서비스, `mydc cd put-local`/`clear-local`과 같다):
  - `GET /t/{t}/apps/{app}/cd/local` → `{tenant, app, revision, localRevision, actor?, document, services, gitServices, conflicts?}`. `revision`은 CD revision(바꾸기의 expected), `localRevision`은 로컬 부분의 revision(0 = 아직 없음), `actor`는 마지막으로 바꾼 사람이다. `document`는 다음 sync를 기다리는 웹 추가분(`services:`만 있는 app.yaml 조각, 없으면 "")이고 mydcd `app-source`의 `pending-local` Section에서 읽는다. `gitServices`는 실행 중인 Git 문서의 서비스라 화면에서 잠근다. `conflicts`는 Git에도 있는 이름이다(그동안 sync가 막히고 `cd.blocked = name-conflict`). CD 앱이 아니면 404.
  - `PUT /t/{t}/apps/{app}/cd/local` `{opId, document, expected?}`. 문서는 앱 업로드(`begin-app-upload` → `put-app-part` × n)로 올리고 `put-app-local-services`가 그 업로드를 가리킨다. 한 opId의 작업이고 같은 opId로 다시 보내면 이어서 한다. `document` ""는 `clear-app-local-services` 하나다(웹 서비스가 없으면 409 `unchanged`). 지금 실행되는 것은 없다. 다음 sync나 승인이 Git 문서에 이 서비스를 더해 실행한다. Git 서비스 이름, Git 서비스를 가리키는 `depends_on`, services 밖 키는 mydcd가 거절한다(op `failed`). expected를 주지 않으면 CD revision을 쓰고 지금 실행 대상(`Target`)에 고정한다. 주면 그 값을 그대로 쓴다. 서비스 1~128개, 1 MiB까지.
- 후보 승인·반려:
  - `POST /t/{t}/apps/{app}/cd/candidate/approve` `{opId, candidate, reason?, expected?}` → `cd-approve`. 승인한 후보는 mydcd가 배포한다.
  - `POST /t/{t}/apps/{app}/cd/candidate/reject` `{opId, candidate, reason?, expected?}` → `cd-reject`. 반려한 commit은 새 commit이나 replan 전까지 후보로 돌아오지 않는다.
  - `candidate`는 보던 `cd.candidateDigest`이고 필수다. 그새 바뀌었으면 409 `candidate-changed`, 후보가 없으면 409 `no-candidate`. `reason`(512자까지, 한 줄)은 작업 원본에 서명되어 이력 행과 이벤트에 남는다. `X-MyDC-Reason` 헤더와 함께 보내면 400이다. expected를 주면 `cd.revision`과 정확히 같아야 하고(strict), 주지 않으면 mydcd가 지금 행보다 새롭지 않은 revision을 받는다. 권한: ManageCD, 또는 이 앱의 승인자(작업 공간 읽기 가능).
  - `GET /t/{t}/apps/{app}/cd/approvers` → `{app, approvers:[username]}`. 이 앱 후보의 승인·반려만 할 수 있는 계정이다(sync·pause·다른 앱·묶음 승인은 안 된다). mydcd CD 기록의 user ID를 작업 공간 구성원 username으로 바꿔 보여 주고, 구성원이 아니면 ID 그대로 둔다.
  - `POST /t/{t}/apps/{app}/cd/approvers` `{opId, user | userId, expected?}` → `grant-cd-approver`, `DELETE` 같은 본문 → `revoke-cd-approver`. user는 작업 공간 구성원의 username(빼기는 목록에 보이는 ID도 됨), userId는 mydcd user ID이고 둘 중 하나만 보낸다. 구성원 중에 없으면 404 `not-found`. 이미 있는 승인자 더하기·없는 승인자 빼기는 op `failed`. expected 기본값은 `cd.revision`.
  - 이벤트(`GET /events`)의 `cd-*` 행에 `cd:{candidateId, commit, fromVersion?, toVersion?, actor?, code?, reason?}`가 붙는다. 종류: `cd-candidate-created`·`cd-approval-required`·`cd-approved`·`cd-rejected`·`cd-sync-started`·`cd-sync-succeeded`·`cd-sync-failed`·`cd-drift-detected`·`cd-paused`·`cd-resumed`·`cd-rolled-back`.
- 앱 버전 목록의 `kind: cd`는 자동 배포가 적용한 버전이다(되돌리기는 예전 버전으로 begin-app).
