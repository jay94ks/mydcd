## 작업 공간 간 연결 (UI-53)

sfcd는 연결을 `resources`의 `route/<보내는 작업공간>/<id>` 행으로 준다. 양쪽 작업 공간의 읽기 권한이 있는 사람이면 누구나 볼 수 있다. 데몬은 망 행에서 서버(node)와 주소 묶음(pool)을 채워 `propose-route` payload를 만든다. 권한, 망이 최신인지, 승인 판단은 sfcd가 한다(ManageRoutes). 응답은 `{op}`이고, `opId` 규칙은 공유 자원 만들기와 같다(target `route/<id>`).

| 끝점 | 본문 → action |
|---|---|
| `GET /t/{t}/routes` | `{items:[R], next:"", networksRevision}` |
| `GET /t/{t}/route-endpoints?tenant=` | `{tenant, items:[{tenant, network, node, pool}]}`: 다른 작업 공간이 연결 받는 쪽으로 연 망(sfcd `PublicRead` `route-endpoints`, REQ-38. 모든 쪽을 읽어 합친다. 활성이고 이름이 있는 TUN 망 멤버만 나온다). 화면의 받는 쪽 망 고르기에 쓴다. 어느 작업 공간의 관리자도 아니면 403 |
| `POST /t/{t}/routes` | `{opId, id?, source:{network, node?}, destination:{tenant, network, node?, pool?}, protocol:"tcp"\|"udp", ports:[443, "8000-8100", {first,last}], expected?}` → `propose-route`. 아래 설명 참고 |
| `POST /t/{t}/routes/{sourceTenant}/{id}/approve` | `{opId, expected?}` → 이 작업 공간 쪽 `approve-route`. Expected는 `expected`(화면이 본 연결 `revision`), 없으면 지금 revision. 이미 승인했으면 409 `already-approved`, 철회 중이면 409 `revoking`, 없으면 404 |
| `POST /t/{t}/routes/{sourceTenant}/{id}/withdraw` | `{opId, expected?}` → 이 작업 공간 쪽 `withdraw-route`. 양쪽 누구나 철회할 수 있다 |

`POST /t/{t}/routes`의 칸:
- **id**: 기본값은 `"rt-" + opId 앞 8자`.
- **서버**: 망이 서버 하나에만 있으면 그 서버를 쓴다. 여러 서버에 있으면 node가 필요하다. 보내는 쪽이면 422 `node-required`, 받는 쪽이면 422 `destination-node-required`.
- **주소 묶음**: 그 서버 멤버의 첫 묶음을 쓴다.
- **받는 쪽 망**: 이 세션이 받는 쪽 작업 공간을 읽을 수 없으면 그 작업 공간이 연결용으로 연 끝점(`PublicRead` `route-endpoints`, REQ-38)에서 고른다. 맞는 것이 없으면 422 `destination-not-open`, 여러 서버면 `destination-node-required`, 한 서버에 묶음이 여럿이면 `destination-pool-required`다.
- **같은 작업 공간끼리**: 422.
- **expected**: 기본값은 지금 `networksRevision`이다.

제안만으로는 승인되지 않는다. 보내는 쪽도 따로 승인해야 한다. 양쪽이 다 승인하면 `active`가 된다.

R = `{key, id, sourceTenant, source:{tenant, network, node, name, cidr?}, destination:{...}, protocol, ports:[{first,last}], phase(pending/active/revoking), approvals:[{tenant, user}], generation, revision, side(source/destination), state}`.
- `network`는 sfcd의 멤버 망 ID다. `name`은 그 쪽의 망 이름이고 양쪽 모두 붙는다(sfcd `RouteNames`). 멤버가 이미 빠졌으면 비어 있다.
- `cidr`는 이 작업 공간 쪽에만 있다. 상대 작업 공간 쪽 CIDR은 sfcd가 빼고 주므로 나오지 않는다(devel/design/virtual-bridge.md 3절).
- `state`는 다음 넷 중 하나다.
  - `active`
  - `waiting-me`: 이 작업 공간이 아직 승인하지 않음
  - `waiting-peer`: 상대 승인을 기다림
  - `revoking`: 철회 중. 양쪽 서버가 닫힘을 보고하면 sfcd가 정리한다.

가짜 어댑터는 철회 뒤 닫힘을 흉내 내지 않아서 `revoking`에 머문다. 고정 자료에 `shop/shop-to-ledger`(shop → payments, TCP 5432, shop 승인, payments 대기)가 있다. 예전 가짜의 `route` 행(host/path/app 모양)은 sfcd에 없는 모양이라 없앴다.
