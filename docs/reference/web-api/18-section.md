## 봉인 파일 상태

`GET /system/seal` → `{state, ready, reason}`. 로그인한 사용자 누구나 읽는다. `state`는 `ready`, `no-key`(`SFC_WEB_SEAL_KEY` 없음), `wrong-key`(기존 파일을 연 키와 다름), `broken`(폴더·파일 문제) 중 하나다. `broken`의 `reason`은 경로가 든 OS 오류라 시스템 관리자에게만 그대로 주고, 다른 사용자에게는 일반 문장을 준다. `ready`가 아니면 키를 보관하는 기능(AI, 외부 DNS, 인증서 자동화, 알림)은 꺼진 상태로 보이고 화면에 `reason`을 보여 준다. 평문으로 대신 저장하지 않는다. 비밀 이름이나 값은 어떤 끝점으로도 다시 내보내지 않는다(입력 때 한 번 받고 이후 끝 4자리만).

저장 형식: `<data-dir>/secrets/<이름>`(폴더 0700, 파일 0600), 비밀 1개당 파일 1개, AES-256-GCM. 머리글은 `sfc-web-seal\0`·판 1·키 식별자 8바이트·nonce 12바이트이고, 추가 인증 데이터는 머리글과 이름이라 다른 이름으로 옮긴 파일은 열리지 않는다. 쓰기는 임시 파일 → fsync → rename → 폴더 fsync. bbolt와 다른 파일이며 웹 백업에 넣지 않는다.
