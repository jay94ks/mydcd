## 서버 추가 (UI-13, 시스템 관리자)

'서버 추가' 마법사 5단계는 `sfcli node add`·`node invitation`·`node promote`와 같다. 가입 명부, 초대 서명, 승인 판단은 sfcd가 맡고, 웹은 아무것도 저장하지 않는다. 초대 파일은 받을 때마다 sfcd에서 새로 읽는다.

1. 새 서버에서 `sfcli identity create <identity_dir>`로 키를 만든다. 화면은 명령만 보여 준다.
2. `POST /nodes` `{opId, id, endpoint, publicKey, joinId}` → `invite-node`(Expected 0). 응답은 `{op}`다.
   - id·joinId: 소문자·숫자·`-`, 글자로 시작(joinId는 `genesis` 불가). endpoint: 정규형 `host:port`. publicKey: 64자 소문자 hex. 아니면 422.
   - ID·키·endpoint·Join ID가 이미 있으면 409 `exists`.
   - 가입 단계는 `GET /nodes` 행의 `join`이다: `invited` → `learner` → `ready`(설치·ACK 끝) → `promoting` → `active`.
3. 초대 파일 받기:
   - `GET /nodes/{node}/invitation` → 서명된 초대 JSON 파일(`Content-Disposition: attachment; filename="sfc-invitation-{node}.json"`, `no-store`). invited·learner·ready인 서버만 있고, 아니면 403이다. 서명이 맞지 않으면 502 `invitation-invalid`.
   - `GET /nodes/{node}/invitation/summary` → `{node, cluster(hex), joinId, approvalRevision, source:{id, key, endpoint}, target:{id, key, endpoint}}`. 4단계 명령에 넣는 값이다. `source.key`는 따로 믿는 서버 키와 대조하라고 안내한다.
4. 새 서버에서 `sfcd --config <node.yaml> join --cluster <cluster> --source-public-key <source.key> --invitation <파일>`을 실행한 뒤 `sfcd --config <node.yaml> run`을 실행한다. 화면은 명령만 보여 준다.
5. `join`이 `ready`가 되면 `POST /nodes/{node}/promote` `{opId, expected?}` → `promote-node`(Expected = 행의 `joinRevision`. 가입 중에는 `revision`과 같다). ready가 아니면 409 `not-ready`. 적용 뒤 `promoting`을 거쳐 `active`·`voter:true`가 된다.
