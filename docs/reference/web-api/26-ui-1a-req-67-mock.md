## 서버 셸

sfcd가 사용자 권한(시스템 관리자, 또는 그 서버의 `NodeShell`)과 정책(클러스터 정책 기본 꺼짐, 서버별 inherit/on/off, sudo 기본 막기)을 검사한다. 통과하면 그 서버의 Seafield Cluster 전용 계정(root 아님)으로 PTY를 연다. 웹은 판단하지 않고 sfcd 결과를 그대로 준다. 키 입력과 화면 내용은 bbolt와 로그에 남기지 않는다. op 기록에는 서명한 열기 요청(서버, 크기)과 끝난 결과만 남는다. 비밀번호와 키는 다루지 않는다.

| 경로 | 설명 |
|---|---|
| `GET /node-shell` | `{enabled, maxSessions, idleSeconds, account, nodes:[{node, shell(inherit/on/off), sudo, enabled(실효), ready, notReady?}], grants:[{user, nodes}], revision}`. 시스템 관리자는 전부 본다. `NodeShell`이 있는 사용자는 허용된 서버와 자기 권한만 본다 |
| `PUT /node-shell` | `{opId, enabled?, maxSessions?(1–16), idleSeconds?(60–86400), expected?}` → `set-node-shell-policy`. 빠진 값은 지금 값으로 채운다. Expected 기본은 `revision` |
| `PUT /node-shell/nodes/{node}` | `{opId, shell, sudo, expected?}` → `set-node-shell-node`. sudo는 sfcd가 전용 계정의 sudo 권한에 반영한다 |
| `PUT /node-shell/grants/{user}` | `{opId, nodes, expected?}` → `set-node-shell-grant`(user는 사용자 ID). `nodes`가 비면 권한을 회수한다 |
| `GET /node-shell/sessions?after=&active=&state=&node=` | `active=1`은 `state=open`(queued·opened·closing)과 같다. `state=closed`는 남아 있는 닫힌 세션(서버마다 최근 200개, sfcd가 정함), `node`는 그 서버만이다. 필터는 sfcd `node-shell-sessions`의 State·Node로 한 번에 읽고, `total`·`next`도 필터 결과다. 그 밖의 값은 400. 응답은 `{items:[{sessionId, user, username, node, account, sudo, state, createdAt, openedAt?, lastActivity?, closedAt?, bytesIn, bytesOut, end?:{code, reason, closedBy?}}], next, total}`. sfcd 그대로 sessionId 오름차순 8개씩이고 `next`를 `after`로 보낸다. 닫힌 세션도 남는다. `state`는 `queued`(수락됨, 아직 안 열림)·`opened`·`closing`(관리자·정책 변경으로 닫는 중)·`closed`. `sessionId`는 open op의 request ID(`shell-<opId>`)다. 시각은 RFC 3339이고 아직 없으면 빠진다. 시스템 관리자는 전부, 그 밖의 사람은 자기 것만 본다 |
| `POST /node-shell/sessions/{id}/close` | `{opId}` → `close-node-shell {SessionID}`(Expected 0). 이미 끝난 세션이면 op `failed` |
| `GET /nodes/{node}/shell?opId=&cols=&rows=` (WebSocket) | `open-node-shell {Node, Cols, Rows}`에 서명하고(requestID `shell-<opId>` = sfcd의 SessionID), op를 먼저 저장한다. 그 다음 sfcd에 submit해 수락(queued 세션, 한도에 들어감)을 받고, 같은 원본으로 PTY를 연다. submit 거절은 sfcd 결과 코드를 이름으로 바꿔 op를 `failed`(errorCode)로 두고 아래 오류로 답한다(Forbidden → `forbidden`, ConditionFailed → 409 `conflict`). 응답을 잃으면 op는 `unknown`으로 남고 작업 화면에서 이어 본다. opId 하나로 셸 하나만 열린다. 쓴 opId를 다시 쓰면 409 `shell-used`. 열기 전에 거절되면 WebSocket 업그레이드 요청에는 소켓을 받아 `{type:"error", status, code, message}` 하나를 보내고 닫는다(브라우저는 거절된 업그레이드의 상태를 읽지 못한다). 그 밖의 요청은 같은 HTTP 오류를 받는다: 403 `forbidden`, 409 `node-shell-disabled` / `node-shell-not-ready` / `limit` / `shell-used`, 503 `node-unreachable`. Origin이 다르면 403 `csrf`(HTTP만). 소켓에서 daemon → 브라우저 메시지는 `{type:"session", session}`, `{type:"stdout", data(base64)}`, `{type:"end", code, reason(exit/idle/closed/policy), closedBy?}`(policy는 정책·권한이 바뀌어 sfcd가 닫은 경우. closedBy `{user, username}`은 누군가 닫았을 때만 온다), `{type:"error", code}`. 브라우저 → daemon 메시지는 `{type:"stdin", data}`, `{type:"resize", cols, rows}`, `{type:"close"}`. 브라우저가 떠나거나 웹 로그인이 끝나면 셸도 닫힌다. 끝나면 op는 `applied`(result code = 종료 코드, idle·closed·policy면 errorCode)가 된다 |
