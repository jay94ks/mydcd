## 알림 (UI-C0)

알림은 사용자별 사본이다. 원본(작업 결과 등)의 권위는 그대로 sfcd·웹 기능에 있다. 기본 90일 보관.

| 끝점 | 뜻 |
|---|---|
| `GET /notifications?unread=1&limit=` | `{items:[{id, kind, severity, tenant, title, body, text?, link, action, createdAt, readAt}], unread}`. 최신순, `limit` 1..500(기본 50). `action: true`는 "지금 내가 할 일". 새 알림은 `text:{title, body?:[...], args?}`(문구 코드와 값)로 저장하고, `title`·`body`는 읽는 사람의 언어(계정 `prefs.language`, 없으면 쿠키 `sfc_lang_user`·`sfc_lang`, `Accept-Language`, 영어)로 만들어 준다. 그 전에 저장된 알림은 `text`가 없고 한국어 `title`·`body` 그대로다. args 값(sfcd 오류 코드, 이름)은 번역하지 않는다 |
| `POST /notifications/{id}/read` | 읽음 → 204. 없으면 404 |
| `POST /notifications/read-all` | 모두 읽음 → 204 |
| `GET`/`PUT /notify-prefs` | `{prefs:{mutedKinds, mutedTenants, browser}}`(GET은 `kinds`도 줌). 끈 종류·작업 공간의 알림은 만들지 않는다. `browser`는 탭이 열려 있을 때 브라우저 알림을 띄울지(웹 푸시 없음) |

지금 만드는 알림: 맨 위 작업이 `failed`가 됨(`op-failed`), `unknown`이 됨(`op-unknown`, 할 일), 배포 작업 완료(`deploy-done`), 저장소 옮기기가 접수·승인되어 서버들이 복사를 시작함(`volume-move-started`). 옮기기 작업이 `rejected`로 끝나도 `op-failed`다. 배포의 단계 작업은 알림을 만들지 않는다. 장애 대응·인증서·웹훅 알림은 각 기능과 함께 붙는다.
