## 조회

| 끝점 | mydcd | 비고 |
|---|---|---|
| `GET /dashboard?tenant=` | `node-summary`, `apps` | `{nodes, apps, appsNext, asOf}`. `nodes`는 `/nodes/summary` 행을 모든 쪽 읽은 것 |
| `GET /nodes?after=` | `members`, `whoami` | 행: `{id, key, endpoint, joinID, join, phase, voter, admitsWork, revision, joinRevision, cordoned, cordonedBy?, cordonedAt?, cordonReason?, scheduling?, pendingOperation?, identity?:{operation, phase, failure?, requestedAt?}, identityRotatedAt?, drain?}`. 데몬이 mydcd `members`의 가입 항목(`membership.Entry`)과 수명 주기 행(`NodeLifecycle`)을 서버 ID로 합친다. 가입 중(invited·learner·ready·promoting)이라 수명 주기 행이 없으면 `phase: pending`이고 `scheduling`·`admitsWork`가 없다. `revision`은 수명 주기 행의 revision(격리·복구·제거·신원 교체의 expected, 행이 없으면 가입 항목 것), `joinRevision`은 가입 항목 revision(promote의 expected), `scheduling.revision`은 막기·풀기의 expected. `pendingOperation`은 수명 주기 행의 끝나지 않은 노드 작업. `cordonReason`은 막을 때 적은 사유(mydcd `Scheduling.Reason`, 비우기로 막힌 경우는 없음), `identityRotatedAt`은 마지막 신원 교체를 요청한 시각(`identity.requestedAt`과 같음, RFC 3339)이다. 쪽은 8행씩 서버 ID 순. 목록 + `voters, quorum, runtimeRevision, operationEpoch, configurationIndex, ledgerEpoch, ledgerRevision`. `operationEpoch`은 서버 작업(topology) 세대, `ledgerEpoch`은 원장 세대(ModuleEpoch, mydcd가 생략하면 1), `ledgerRevision`은 원장 root revision(whoami `LedgerRootRevision`) |
| `GET /nodes/summary?tenant=&node=&after=` | `node-summary` | `tenant`가 없으면 클러스터 전체(시스템 관리자), 있으면 그 작업 공간 보기 권한으로 허용 서버만. 행: `{node, status, state, ready, stale, role?, cpuPercent?, memUsed?, memTotal?, diskUsed?, diskTotal?, containers, observedAt(Unix 초), observeLimitSeconds, cordonedBy?, cordonedAt?, scheduling}`. `state`는 mydcd 값(ready/unready/unreachable/pending/서버 단계), `status`는 화면 말(unready→degraded, 나머지는 state 그대로). `role`·`cpuPercent`·총량은 클러스터 전체 보기에서만, 작업 공간 보기는 그 작업 공간의 `containers`(와 mydcd가 주면 `memUsed`)만 |
| `GET /nodes/{node}/tasks?tenant=&after=` | `tasks` | |
| `GET /nodes/{node}/storage?after=`, `GET /storage?after=` | `node-storage` | 행: `{node, id, path, tenants, maxVolumes, generation, revision, draining, attested, closed, volumes?}`. `attested`는 서버가 저장 경로를 확인함(그래야 고정 볼륨을 만든다), `closed`는 꺼낸 뒤 서버가 닫았다고 알림. `volumes`는 데몬이 `volumes` 목록에서 센 고정 볼륨 수(못 읽으면 없음). mydcd는 만드는 중인 볼륨도 세므로 지우기 판단은 mydcd 결과가 정한다 |
| `GET /nodes/{node}/storage/{id}/space` | `node-storage-space` | 시스템 관리자. `{node, id, generation, total, free, available, observedIndex}`. `generation`은 표본을 잰 저장 경로 세대, `observedIndex`는 mydcd가 읽은 원장 index |
| `GET /nodes/{node}/disks?tenant=&after=`, `GET /disks?tenant=&node=&after=` | `node-disks` | `tenant`가 없으면 클러스터 전체(시스템 관리자), 있으면 그 작업 공간의 볼륨 관리 권한으로 그 작업 공간을 허용한 저장 경로 디스크만(장치 이름 없음). 행: `{node, id, mount, device?, fsType, state(observed/unknown), purpose, purposes, storageRootID?, storageRoots, total?, used?, free?, available?, inodesFree?, observedAt(Unix 초), stale}`. 한 파일 시스템에 용도·저장 경로가 여럿이면 `purposes`·`storageRoots`에 모두, `purpose`·`storageRootID`는 첫 값. 크기는 관측 전이면 없음 |
| `GET /raft` | `raft-status` | 시스템 관리자. `{leader, observedBy, term, commitIndex, appliedIndex, configurationIndex, voters, quorum, respondingVoters, stale, servers, lastSnapshotIndex?, lastSnapshotAt?, elections, electionsDropped?, observedAt}`. `servers` 행: `{node, suffrage(voter/non-voter), role(leader/follower/candidate/non-voter/pending), matchIndex?, appliedIndex?, lag?, snapshotIndex?, logEntries?, logBytes?, lastContactAt?, stale}`. 숫자는 서버가 알리지 않았으면 없음. `elections`: `{term, leader, at, reason}`. 시간은 Unix 초. 마지막 스냅숏은 관측하는 서버(`observedBy`) 값 |
| `GET /raft/compact` | `raft-status`(`LastManualCompact`) | `{retain, minimal, entries:{node: 스냅샷 뒤 로그 건수}, last?:{operation, id?(웹 opId), at, by, mode: keep\|minimal, state: running\|done\|failed, nodes:[{node, state: queued\|running\|done\|failed\|skipped, snapshotIndex?, snapshotBytes?, logBytesBefore?, logBytesAfter?, durationMs?, error?}]}}`. `retain`(10240)·`minimal`(1000)은 mydcd가 설정값을 아직 주지 않아 고정값. `id`·`by`(이름)는 이 웹에서 보낸 작업일 때만, 아니면 `by`는 사용자 ID. `nodes`는 서버 이름 순이고 `error`는 mydcd의 실패 코드 |
| `POST /raft/compact` | `raft-compact-plan`, `raft-compact` | `{opId, nodes[](비우면 설치된 투표 서버 전부, 투표하지 않는 서버도 이름을 적으면 넣을 수 있음), mode: keep\|minimal, serial, plan}` → `{op}`. `plan`은 미리보기의 `plan`(대상 지문, 64 hex)이고 꼭 보내야 한다. 없거나 모양이 틀리면 422 `invalid`, 보여 준 뒤 대상이 바뀌었으면 409 `plan-changed`. 데몬이 선택(`control.CompactSelection{Nodes, Mode, Retain: minimal이면 1000, Parallel: !serial}`)으로 계획을 모두 읽어 Target을 얻고 `CompactChange{Operation: "op-"+opId, Selection, Target}`(Expected 0)를 보낸다. 마지막 압축이 아직 진행 중이면 409 `in-progress`, 읽는 사이 서버 구성이 바뀌면 409 `plan-changed`. 같은 서버가 다른 작업에 걸려 있는 등 거절은 mydcd가 판단한다. 권한도 mydcd가 정한다(시스템 관리자) |
| `GET /raft/compact/plan?nodes=a,b&mode=&serial=` | `raft-compact-plan` | 미리보기 `{mode, retain?, parallel, total, nodes(실행 순서, leader 마지막), plan(대상 지문 64 hex)}`. 수락 때 mydcd가 다시 검사한다. 없는 서버를 고르면 mydcd가 거절한다(403) |
| `GET /raft/compactions/{operation}` | `raft-compact-status` | 한 작업의 권위 있는 진행: `{operation, by(사용자 ID), at, mode, retain?, sequential, complete, total, queued, running, done, failed, skipped, nodes:[{node, state, code?, revision}]}`. 모든 쪽을 읽어 합친다. 없으면 404(mydcd는 아직 모르는 작업을 conflict로 답하고, 웹은 첫 쪽의 conflict를 404로 보인다). snapshot·로그 수치는 `GET /raft/compact`에 있다 |
| `GET /mesh?tenant=&node=&after=` | `mesh-links` | `tenant`가 없으면 클러스터 전체(시스템 관리자), 있으면 그 작업 공간 보기 권한으로 허용 서버 사이 연결만. 행: `{id(PairID), nodeA, nodeB, state(up/degraded/down/pending), rttMillis?, lossPercent?, lastHandshakeAt?, lastChangeAt?, observedBy?, observedAt(Unix 초), stale}`. 양쪽 관측값(`rttMillis` 등)은 mydcd가 클러스터 전체 보기에서만 주며 두 쪽 중 나쁜 값을 쓴다 |
| `GET /node-cli-policy` | `node-cli-policy` | |
| `GET /events?tenant=&app=&node=&kind=&since=&limit=` | `events` | `tenant`가 없으면 클러스터 전체(시스템 관리자). `limit`은 최대 100. 행: `{cursor, time(Unix 초), scope, tenant?, app?, node?, network?, pairId?, kind, target, detail, cd?, ingress?, shellClosedBy?}`. `target`·`detail`은 데몬이 mydcd의 Target·Detail 필드로 만든 한 줄(작업 `tenant/app/service/task`, 서버 쌍은 pairId, 파일 시스템은 `node:id`). `ingress`는 gateway·route·host·prefix·value(mydcd는 listener를 주지 않는다). `next`는 남은 행이 있을 때만, 다음 `since`로 쓴다(없으면 마지막 행 cursor). 만료 cursor는 409 `cursor-expired` |

| `GET /tenants/{t}/retirement?after=` | `tenant-retirement` | `{tenant, retiring, revision, phase(active/retiring/deleted), operation(종료 중이 아니면 ""), targetCount, ownerCount, closedOwners, remainingCount, remaining, next, ready}`. `revision`은 작업 공간 revision(종료 시작·마치기의 `expected`). `ready`는 데몬이 계산: retiring이고 모든 소유자가 닫았다고 보고했으며(`closedOwners == ownerCount`) 남은 것이 0 |

| `GET /t/{t}/storage?after=` | `tenant-storage`(REQ-30·58) | 이 작업 공간이 쓸 수 있는 저장 경로(한 쪽 8개). 작업 공간 관리 권한(볼륨 또는 레지스트리 관리)이 필요하고 보기 권한만 있으면 403이다. 행: `{node, id, generation, revision, draining, allowed, root:{cluster, node, key, id, generation, path}, volumes?}`. `maxVolumes`·`attested`는 이 행에 없다(시스템 관리자는 `/storage`에서 본다). `root`는 빌드 정책이 이름 붙이는 전체 참조다. 다른 작업 공간은 mydcd가 알려 주지 않는다. `generation`은 `register-fixed-volume`의 `rootGeneration`이다. `volumes`는 데몬이 이 작업 공간 `volumes` 목록에서 센 고정 볼륨 수(못 읽으면 없음) |
