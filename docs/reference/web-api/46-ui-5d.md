## 가상 브릿지 (UI-5D)

망 두 개를 통째로 잇는다(devel/design/virtual-bridge.md). sfcd는 브릿지를 `resources`의 `bridge/<만든 작업 공간>/<이름>` 행으로 준다. 양쪽 작업 공간의 읽기 권한이 있는 사람이면 누구나 볼 수 있다. 권한, 상대 망의 `bridge-inbound`, 최신인지 판단은 sfcd가 한다(TM(Network)). 응답은 `{op}`이고, `opId` 규칙은 공유 자원 만들기와 같다(target `bridge/<이름>`). 데몬이 이 작업 공간의 행에서 볼 수 있는 것은 먼저 거절한다. 나머지 sfcd 거절은 op의 `state: failed`와 `errorCode`(아래 사유)로 온다.

> 지금은 만들기·승인·닫기와 행까지다. 열린 브릿지로 패킷이 다니는 부분은 아직 만드는 중이다.

| 끝점 | 본문 → action |
|---|---|
| `GET /t/{t}/resources` | 행 `{key:"bridge/<owner>/<name>", tenant:<owner>, bridge:B}` |
| `GET /t/{t}/bridge-endpoints?tenant=` | `{tenant, items:[{tenant, network}]}`: 다른 작업 공간에서 브릿지를 받는 망(sfcd `PublicRead` `bridge-endpoints`). `bridge-inbound`를 켰고 바뀌는 중이 아닌 TUN 망의 이름만 나온다. 만들기 대화상자의 상대 망 고르기에 쓴다. 상대 작업 공간을 읽을 권한은 없어도 된다. 어느 작업 공간에서도 망을 관리할 수 없으면 403, `tenant`가 비었거나 이 작업 공간이면 422 |
| `POST /t/{t}/bridges` | `{opId, name, network, peer:{tenant?, network}, direction?, protocol?, ports?, expected?}` → `create-virtual-bridge` |
| `POST /t/{t}/bridges/{owner}/{name}/approve` | `{opId, expected?}` → 이 작업 공간 쪽 `approve-virtual-bridge`. 다른 작업 공간이 만든 대기 중 브릿지만 승인한다. 아니면 409 `already-approved` |
| `POST /t/{t}/bridges/{owner}/{name}/close` | `{opId, expected?}` → `close-virtual-bridge`. 양쪽 누구나 닫는다. 대기 중이면 바로 사라지고, 열린 것은 `closing`이 된 뒤 모든 서버가 정리를 보고하면 사라진다. 이미 닫는 중이면 409 `closing`, 없으면 404 |
| `POST /t/{t}/networks/{name}/toggles` | `{opId, toggle:"bridge-inbound", on}`: 다른 작업 공간이 이 망으로 브릿지를 만들 수 있게 한다. 서버 수와 상관없다. 끄면 새 요청과 대기 중 브릿지의 승인만 막는다 |

`POST /t/{t}/bridges`의 칸:
- **name**: 만든 작업 공간 안에서 고유한 이름(영소문자·숫자·`-`).
- **network**: 이 작업 공간의 TUN 망. **peer.tenant**를 비우면 같은 작업 공간이다. 같은 작업 공간이면 승인 없이 바로 열린다(`open`). 다른 작업 공간이면 상대 관리자가 승인해야 열린다.
- **direction**: `both`(기본), `a-to-b`(이 망에서만 시작), `b-to-a`(상대 망에서만 시작).
- **protocol**: `all`(기본), `tcp`, `udp`. **ports**는 tcp·udp에만 쓸 수 있고 `/routes`와 같은 모양이다(`443`, `"8000-8100"`, `{first,last}`). 비우면 모든 포트다.
- **expected**: 기본값은 지금 망 목록 revision이다.

오류:
- 422 `invalid`: 이름, 망, 방향, 프로토콜, 포트. `sfc-system`과 같은 망끼리는 잇지 않는다.
- 409 `bridge-exists`: 같은 두 망 사이에 브릿지가 이미 있다(방향과 상관없이 하나뿐).
- 409 `network-changing`: 이 작업 공간 쪽 망이 바뀌는 중이다.
- op `errorCode`(sfcd): `bridge-exists`, `peer-closed`(상대 망이 없거나, 브릿지를 받지 않거나, 바뀌는 중. 셋을 구분하지 않는다), `network-changing`, 그리고 망 지우기나 마지막 서버 빼기가 걸린 브릿지 때문에 막히면 `bridge-attached`.

B = `{state, kind:"bridge", owner, name, a:{tenant, network}, b:{tenant, network}, direction, protocol, ports:[{first,last}], phase(pending/open/closing), approvals:[{tenant, user}], generation, revision}`.
- `a`는 만든 쪽이다. 양쪽 모두 망 이름만 나오고 CIDR은 나오지 않는다.
- `state`(이 작업 공간 기준): `open`, `closing`, `waiting-me`(이 작업 공간이 아직 승인하지 않음), `waiting-peer`(상대 승인을 기다림).
- 승인·닫기의 Expected는 브릿지 `revision`이다.

가짜 어댑터는 만들기·승인·닫기와 거절 사유를 흉내 낸다. 닫힘 보고는 흉내 내지 않아서 `closing`에 머문다. 망 지우기의 `bridge-attached`도 흉내 내지 않는다.
