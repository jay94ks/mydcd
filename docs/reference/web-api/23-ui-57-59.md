## 인증서 자동화 (UI-57~59, 시스템 관리자)

웹 전용 ACME다(인증서 자동화 계획). DNS-01만 쓰고, `_acme-challenge` TXT는 외부 DNS 연동의 공급자로 만들고 지운다(바꾸는 동안 `dns-managed`에 `acme:<인증서>`로 표시). 새 비공개 키는 발급마다 웹 메모리에서 만들어 **클러스터 인증서 보관함**에만 넘기고 버린다. bbolt에는 공개 정보(지문=보관함 인증서 ID·SAN·발급자·유효 기간)와 공개 체인만 둔다. ACME 계정 키는 봉인 파일 `acme-<계정ID>`.

인증 기관: 실행 파일에는 Let's Encrypt 실제(`letsencrypt`)와 시험용(`letsencrypt-staging`)이 있다([rfc8555.go](../../../internal/web/acme/rfc8555.go), golang.org/x/crypto/acme). 아직 실제 Let's Encrypt로 돌려 보지 않았으므로 처음에는 시험용 계정으로 받아 보고, [공급자 진단 로그](45-provider-log.md)를 켜 둔다. 프로세스 안 가짜 인증 기관(`fake`, 아무도 신뢰하지 않는 루트)은 server 시험에만 있다.

검증 방식은 이름마다 정한다. 연결된 외부 도메인 아래 이름은 DNS-01, 그 밖의 와일드카드가 아닌 이름은 HTTP-01 응답기(`-acme-listen`)가 켜져 있을 때 HTTP-01이다. 둘 다 안 되면 인증서 만들기가 `422 no-domain`이다. HTTP-01 이름은 클러스터 도메인 목록([sfcli domain](../../cli/domain.md)) 아래여야 한다. ingress가 등록된 도메인 호스트의 `/.well-known/acme-challenge/`만 응답기로 넘기기 때문이다. 아니면 주문이 인증 기관에 묻기 전에 `not-registered`로 멈춘다.

DNS-01 반영 확인은 두 가지가 모두 보여야 끝난다: DNS 공급자 API에 TXT 값이 있고, 그 도메인의 권한 네임서버(공개 해석기로 찾은 NS) 전부가 비재귀 질의에 그 값을 답한다. 최대 10분 기다린다.

인증서 보관함(REQ-21, [certificate-store.md](../certificate-store.md)): `store` 단계는 **발급을 누른 사람의 sfcd 세션**으로 간다. 먼저 체인과 키를 sfcd의 보호 입력(`certificate`)에 한 번 넘기면, sfcd가 키를 봉인하고 공개 receipt를 준다(같은 요청 ID `web-cert-acme-<주문 ID>`와 같은 입력으로 다시 물으면 같은 receipt). 그 receipt만 담은 `put-certificate` 원본을 서명해 그 사람의 작업 목록에 `acme-<주문 ID>`로 저장한 뒤 보낸다(`orders[].storeOp`가 그 작업 ID). 원본에는 키가 없다. 응답을 잃으면 **같은 원본으로만** 2초·5초·10초 뒤 다시 보낸다. 그래도 모르면 주문은 `store-unknown`으로 끝나고 키는 버린다. 그 작업은 `/ops/acme-<주문>/result`로 결과를 읽고 `resume`으로 같은 원본을 다시 보낼 수 있다. 저장된 인증서 ID는 leaf 지문이고 정의의 `fingerprint`와 같다. 새로 발급한 leaf이므로 같은 ID가 이미 있는 일은 없다. `certStore`는 항상 `true`(보관함은 각자 세션으로 쓴다).

| 끝점 | 뜻 |
|---|---|
| `GET /acme/cas` | 로그인. `{items:[{id, name, directory, staging, needsEab, caa, keyTypes, ready, note}]}` |
| `GET`/`POST /acme/accounts` | `{ca, email?, agreeTos:true, eab?:{keyId, hmac(base64)}}` → 201 `{account:{id, ca, email, url, eab, agreedAt}}`. 계정 키는 웹이 만들어 봉인 |
| `DELETE /acme/accounts/{id}` | 인증서가 쓰면 409 `in-use` |
| `GET /acme/certs` | `{items:[{name, names, account, keyTypes, autoRenew, fingerprint, keyType, issuer, notBefore, notAfter, nextRenew, nextTry, failures, lastOrder, running}], certStore}` |
| `POST /acme/certs` | `{name(웹 정의의 이름, a-z0-9-. 보관함에는 이름이 없다), names:["shop.example.com","*.shop.example.com"], account, keyTypes?(기본 ["ec256","ec384","rsa3072"]), autoRenew?(기본 true)}` → 201. 이름마다 연결된 외부 도메인이 있어야 한다(아니면 422 `no-domain`) |
| `GET /acme/certs/{name}` | `{certificate, orders(최근 20개), methods:{"<이름>": "dns-01"\|"http-01"\|null}, methodReasons:{"<이름>": "no-domain"\|"not-registered"}}`. `methods`는 지금 발급하면 이름마다 쓸 방식이다(읽기 전용, 서버가 정한다). null인 이름은 `methodReasons`에 이유가 있다. 도메인 목록을 읽지 못하면 HTTP-01 이름은 확인하지 않고 `http-01`로 둔다 |
| `PUT /acme/certs/{name}` | `{autoRenew, keyTypes}` |
| `DELETE /acme/certs/{name}` | 정의만 지운다. 보관함 인증서는 그대로 |
| `POST /acme/certs/{name}/issue` | `{opId}` → 202 `{order}`. 뒤에서 돈다(창을 닫아도 계속). 같은 opId는 그 주문을 돌려주고, 이미 도는 주문이 있으면 409 `running` |
| `GET /acme/certs/{name}/chain` | 공개 체인 PEM 내려받기(비공개 키 없음) |
| `POST /acme/certs/{name}/revoke` | `{confirm:"<name>", reason?: keyCompromise\|superseded\|cessationOfOperation\|unspecified(기본)}` → 인증 기관에 해지(계정 키로 서명). 되돌릴 수 없다. 자동 갱신을 끈다. 다른 reason은 422. Let's Encrypt는 계정 키로 서명한 `keyCompromise`를 거절할 수 있다(그때 502 `ca-revoke`) |

주문 단계(`orders[].steps[]`, 각 `{name, state, at, detail}`): `preflight`(계정·키 형식·이름마다 외부 도메인·CAA) → `order` → `txt` → `propagation`(공급자가 TXT를 내줄 때까지, 최대 10분) → `validate` → `finalize`(새 키·CSR·발급) → `store`(보관함에 넣기, `detail`은 인증서 ID) → `cleanup`(TXT 지우기). 실패 코드: `renew-account`(자동 갱신, 아래), `account`, `key-type`, `no-domain`, `not-registered`(HTTP-01 이름이 등록된 도메인 아래가 아님), `caa-blocked`, `dns-<종류>`, `ca-order`, `propagation`, `ca-validate`, `ca-finalize`, `store-prepare`(서명·저장 전 실패, 보내지 않음), `store-rejected`(sfcd가 실행 전에 거절, 예: 로그인 만료), `store-failed`(결과 코드가 적용 아님), `store-unknown`. 실패해도 TXT는 지우고, 못 지운 것은 `orphanTxt`.

키 형식은 `keyTypes` 순서에서 인증 기관이 받는 첫 번째로 받고, 1순위가 아니면 알림을 남긴다. 갱신은 매시간 검사해 유효 기간이 1/3 남으면(`nextRenew`) 사람 없이 돈다(`auto:true`). 실패하면 1시간 → 6시간 → 하루 뒤 다시(`nextTry`). 만료 14·7·3일 전에 정의를 만든 사람에게 알림(`certificate`, 할 일). 사람 없는 갱신은 웹 자동 작업 계정(아래 "자동 작업 계정")으로 로그인해 `put-certificate`에 서명한다(주문의 `by`는 "자동 갱신", 저장 op는 그 계정의 것). 그 계정이 인증서 보관함에 쓸 수 있는지는 sfcd가 정한다. `preflight`에서 먼저 로그인해 보고, 안 되면 인증 기관에 묻기 전에 `renew-account`로 멈춘다. 저장 단계에서 다시 로그인한다(sfcd는 놀고 있는 연결을 30초 뒤 닫는다). `renew-account`도 다른 실패처럼 재시도 일정(`nextTry`)에 넣고 알린다. 자동 작업 계정이 없으면 **주문을 시작하지 않고**, 실패로 세지 않으며(`failures`·`nextTry` 그대로) 갱신 시점마다 정의를 만든 사람에게 '인증서 직접 갱신 필요' 알림(할 일)을 한 번 남긴다(`renewBlocked`).

발급 도중 로그아웃하거나 로그인이 만료되면 `store` 단계가 `store-prepare` 또는 `store-rejected`가 되고, 인증 기관이 발급한 인증서는 키와 함께 버려진다(다시 발급한다).

아직 없는 것: 사람 없는 갱신의 보관함 올리기(REQ-9 위임 계정), 실제 sfcd 보관함, ARI, 요청 수 제한 미리 세기, 공개 해석기로 반영 확인, 작업 공간 사용자의 'HTTPS 자동', Let's Encrypt 실제 ACME 클라이언트.

### 자동 발급 (UI-57, 웹 몫, 시스템 관리자)

설정은 웹 bbolt(`acme-auto`)에 둔다. 감시하는 호스트는 sfcd의 외부 접속 매핑을 장애 감시와 같은 자동 작업 계정 세션으로 1분마다 읽어서 정하고, 웹에 복사해 두지 않는다. 대기 목록은 데몬 메모리에만 있어 재시작하면 `since`가 새로 시작한다.

- **감시 대상**: :443 수신 주소가 있는 인스턴스의 경로 규칙 호스트 중, 보관함의 만료되지 않은 인증서 호스트(정확히 같거나 한 단계 위 `*.`)와 맞지 않는 것이다. 무시한 호스트는 뺀다.
- **정의가 이미 있는 경우**: 이름이 맞는 웹 ACME 정의가 있으면 그 정의의 주문을 따른다. 마지막 주문이 `caa-blocked`나 `rate-limit`로 실패했으면 대기 목록에 그 이유로 올린다.
- **정의가 없는 경우**:
  - 공급자가 연결된 도메인 밑이면 DNS-01, 아니면 클러스터 도메인 목록의 도메인 밑일 때 HTTP-01로 받는다. 둘 다 아니면 `not-registered`이다.
  - HTTP-01인데 이 웹 앱의 응답기(`-acme-listen`)가 꺼져 있거나 클러스터 응답기 주소가 비어 있으면 `no-responder`이다.
  - 공급자가 연결된 도메인에서, 그 호스트를 쓰는 작업 공간에 그 이름이 도메인 배정(레코드와 같은 규칙)으로 없으면 `not-assigned`이다. 공급자 없는 도메인은 배정이 없으므로 보지 않는다(경로 규칙 자체가 sfcd가 받아들인 호스트다).
  - 그 도메인의 자동 발급이 꺼져 있거나 계정이 없으면 `auto-off`이다.
  - 둘 다 아니면 정의를 만들고 바로 주문한다.
    - 정의의 모양: `autoIssued:{host, detectedAt}`, `createdBy:"자동 발급"`, 자동 갱신 켬, 키 형식은 도메인 것이 있으면 그것을 쓰고 없으면 기본값을 쓴다.
    - 이름: `per-host`면 호스트 이름의 점을 `-`로 바꾼다. `wildcard`(공급자가 연결된 도메인만)면 도메인 바로 밑 호스트를 `*.도메인` 하나로 묶고 이름은 `wild-…`이다. 더 깊은 호스트는 호스트마다 따로 받는다.
    - `wildcard`는 그 호스트 하나의 배정만 보고 `*.도메인`을 받으므로, 다른 작업 공간에 배정된 같은 단계 이름도 덮는다(보관함은 클러스터 공용).
    - 주문은 사람 없는 갱신처럼 자동 작업 계정으로 서명한다. 보관함에 쓸 수 있는지는 sfcd가 정한다.
- **한 라운드 상한**: 새 정의와 주문은 한 라운드에 3개까지다(인증 기관 요청 수 한도). 나머지는 다음 라운드에 만든다.
- **알림**: 대기가 `notifyAfterMinutes`분을 넘으면 설정을 마지막에 바꾼 관리자에게 알린다(`certificate`, 할 일, 호스트마다 한 번).
- 도메인 하나라도 자동 발급이 켜져 있으면 장애 대응이 꺼져 있어도 감시는 계속 돈다.

| 끝점 | 뜻 |
|---|---|
| `GET /acme/auto` | `{enabled(새 도메인 기본값), account?, keyTypes, dualRsa, notifyAfterMinutes, domains:[{domain, enabled, mode: per-host\|wildcard, keyTypes?, tenants}], waiting:[{host, reason: not-registered\|no-responder\|not-assigned\|auto-off\|caa-blocked\|rate-limit, tenant?, app?, node, listen, since}], revision}`. `domains`는 공급자가 연결된 도메인과, 감시가 마지막으로 읽은 클러스터 도메인 목록을 합친 것이다. `tenants`는 그 도메인의 작업 공간 배정과, 감시 중에 본 작업 공간을 합친 것이다 |
| `PUT /acme/auto` | 위 모양에서 `waiting`을 뺀 것(`domains[].tenants`는 받기만 하고 무시) → 같은 모양. revision이 다르면 409 `stale`이다. 켜려면 `account`가 필요하다. `keyTypes`는 1~5개, `notifyAfterMinutes`는 1~1440이고, 모르는 도메인이거나 공급자 없는 도메인에 `wildcard`면 422 `invalid`이다. `domains`가 있으면 클러스터 도메인 목록을 로그인한 사용자로 읽는다 |
| `POST /acme/auto/ignore` | `{host}` → 같은 모양. 그 호스트를 감시에서 뺀다. 대기 목록에 없으면 404 |

`dualRsa`는 저장만 한다. 한 호스트에 RSA와 EC를 함께 내보내는 일은 외부 접속(sfcd)이 아직 못 한다.

### HTTP-01 응답기 주소 (sfcd 설정, 웹이 채움)

ingress는 등록된 도메인 호스트의 평문 HTTP에서 `/.well-known/acme-challenge/`만 클러스터 설정 응답기 주소로 넘긴다([도메인 명령](../../cli/domain.md#acme-http-01-응답기)). 웹은 `-acme-listen`(`SFC_WEB_ACME_LISTEN`)이 켜져 있으면 그 주소를 직접 채운다. 넣는 주소는 `-acme-advertise IP:PORT`(`SFC_WEB_ACME_ADVERTISE`, ingress가 TUN 망에서 닿는 주소)이고, 없으면 `-acme-listen`이 구체적인 IP:port일 때 그 값이다. `0.0.0.0:80`이나 `:80`처럼 듣는 주소만 있고 `-acme-advertise`가 없으면 채우지 않는다.

- **위임이 필요하다**: 채우기는 웹 자동 작업 계정(장애 감시와 같은 세션)이 `set-acme-responder`(시스템 관리자 동작)에 서명해 보낸다. 그 계정은 시스템 관리자여야 하고, credential의 허용 동작 목록을 정해 두었다면 `put-certificate`와 함께 `set-acme-responder`도 넣어야 한다([인증서 보관함](../certificate-store.md)). 아니면 sfcd가 거절하고, 웹은 진단 로그에 경고만 남긴 채 1분마다 다시 해 본다. 관리자가 `sfcli domain acme-responder set`으로 직접 넣어도 된다.
- 설정이 이미 같은 주소면 보내지 않는다. 한 번 맞으면 데몬이 다시 시작할 때까지 더 보지 않는다. 웹은 설정을 지우지 않는다(지우기는 `sfcli domain acme-responder clear`).

| 끝점 | 뜻 |
|---|---|
| `GET /acme/responder` | 시스템 관리자. `{listening, advertised?, address?, setBy?, setAt?}`. `listening`은 이 웹이 응답기를 띄웠는지, `advertised`는 웹이 채우는 주소, `address`·`setBy`·`setAt`은 sfcd 클러스터 설정(없으면 비어 있고 그 경로는 404) |

### 인증서 보관함 (UI-57·59, sfcd 몫)

보관함 자체는 sfcd 것이다([certificate-store.md](../certificate-store.md)). 웹은 **로그인한 사람의 sfcd 세션**으로 읽고 바꾸며, 누가 볼 수 있는지도 sfcd가 정한다(시스템 관리자만, 아니면 403). 인증서에는 이름이 없고 ID(leaf DER의 SHA-256, 16진수 64자)로 가리킨다. 경로의 `{id}`는 앞 12자 이상이면 되고, 둘 이상과 맞으면 409 `ambiguous`, 없으면 404. 웹은 보관함을 복사해 두지 않는다. 목록은 sfcd의 `certificates`를 32행씩 끝까지 읽는다(도중에 보관함이 바뀌어 conflict면 처음부터 다시, 3번까지). 어느 서버가 내보내는지는 외부 접속 조회 `ingresses` 매핑의 `Runtime.Certificates`(서버·host마다 인증서 ID·만료·오류)를 쓴다.

인증서 행 `StoreCert`: `{id, names, keyType(ecdsa-p256|ecdsa-p384|rsa-2048…), issuer(DN), serial(콜론으로 끊은 16진수), notBefore, notAfter, uploadedBy(사용자 이름, 못 찾으면 ID), uploadedAt, state: linked|unlinked|pending-destroy, disabled, links:[{host, alg: ecdsa|rsa, servedBy?}], definition?, chain?}`. `definition`은 그 인증서를 받은 웹 ACME 정의의 이름이다. 링크·상태 규칙은 [sfcli certificate](../../cli/certificate.md#호스트와-연결)와 같다.

| 끝점 | 뜻 |
|---|---|
| `GET /certificates?host&state` | `{items:[StoreCert], store:true}`(NotAfter 늦은 것부터). `host`는 그 호스트를 덮는 인증서만, `state`는 `unlinked`나 `pending-destroy`만 |
| `GET /certificates/{id}` | `StoreCert`에 `chain`(체인의 subject들, leaf부터)과 링크마다 `servedBy`(지금 그 인증서로 그 호스트를 내보내는 서버) |
| `GET /certificates/{id}/chain` | 공개 체인 PEM 내려받기(비공개 키 없음) |
| `POST /certificates/check` | `{chain}` → `{id, names, keyType, issuer, notAfter, links:[{host, alg, replaces?}], invalid?: expired\|not-yet-valid\|unsupported-key\|no-names}`. 체인만 읽는다(키는 받지 않음). `links`는 올리면 생길 링크이고 `replaces`는 그 링크를 지금 가진 인증서 ID다. 체인이 아니면 422 `invalid-chain` |
| `POST /certificates` | `{chain, key}` → 201 `{id, created:true, links}`. 같은 ID가 이미 있으면 보내지 않고 200 `{id, created:false, links}`. 웹이 먼저 검사한다: 422 `invalid-chain`, `invalid-key`, `mismatch`(키가 체인의 것이 아님), `not-valid-now`, `unsupported-key`, `no-names`. 그다음 키를 **sfcd 보호 입력으로 한 번만** 넘기고(요청 ID `web-cert-<op ID>`), 받은 공개 receipt만 담은 `put-certificate` 원본을 서명 → 그 사람의 작업으로 저장 → 보낸다. sfcd가 거절하면 422 `invalid-certificate`. 키는 bbolt·로그·응답·원본 어디에도 남지 않는다. 장애 대응에서 온 사유는 원본에 함께 서명한다 |
| `POST /certificates/{id}/disable` | → `{unlinkedHosts}`(disable-certificate `{ID}`). 링크를 모두 떼고 `파기 대기`로 보낸다. 이미 끊었으면 409 `disabled` |
| `DELETE /certificates/{id}` | → 204(delete-certificate `{ID}`). 링크가 있으면 보내지 않고 409 `{error:{code:"linked"}, links}` |

바꾸는 요청이 sfcd에서 거절되면 그 작업 결과의 코드로 답한다. 응답을 잃은 작업은 작업 목록에서 `resume`으로 같은 원본을 다시 보낸다.
