## 외부 DNS (UI-54~56)

웹 앱이 DNS 공급자를 직접 부른다(외부 DNS 연동 계획). 도메인 목록은 클러스터 도메인 목록([sfcli domain](../../cli/domain.md), 인증서 보관함 첫 페이지의 `Domains`)이고, 웹 앱은 거기에 자기 몫(공급자 연결·기본 TTL·작업 공간 배정)만 더한다. 등록·빼기는 로그인한 사용자의 `add-domain`·`remove-domain`이다. 공급자가 없는 도메인은 레코드를 읽거나 바꿀 수 없고(409 `no-provider`), 인증서는 HTTP-01로만 받는다. 공급자 토큰은 봉인 파일 `dns-<연결ID>`에 두고 다시 보여 주지 않는다(끝 4자리만). 봉인이 준비되지 않았으면 503 `seal-unavailable`.

공급자 오류는 `dns-<종류>` 코드로 바뀐다: `dns-auth-failed`·`dns-forbidden`(502), `dns-not-found`(404), `dns-rate-limited`(429, `Retry-After`), `dns-invalid`(422), `dns-conflict`(409), `dns-unavailable`(502). 원문은 `error.detail`.

공급자 어댑터: 실행 파일에는 Hostinger(`hostinger`, [hostinger.go](../../../internal/web/dns/hostinger.go))가 있다. 가짜 공급자 `fake`는 server 시험에만 있다. Hostinger 어댑터는 실제 계정에서 아직 시험하지 않았다. 처음 쓸 때는 [공급자 진단 로그](45-provider-log.md)를 켜 두면 호출 기록으로 문제를 찾을 수 있다.

| 끝점 | 권한 | 뜻 |
|---|---|---|
| `GET /dns/vendors` | 로그인 | `{items:[{id, name, tokenUrl, ready, note, capabilities}], sealReady}` |
| `GET /dns/providers` | SA | 연결 목록 `{items:[{id, vendor, name, tokenHint, tokenExpires, account, lastCheck, lastCheckOk, lastError, remaining}]}` |
| `POST /dns/providers` | SA | `{vendor, name, token}` → 201 `{provider, account}`. 토큰을 시험(`Check`)한 뒤에만 봉인한다 |
| `POST /dns/providers/{id}/check` | SA | 다시 시험하고 결과를 남김 |
| `PUT /dns/providers/{id}/token` | SA | `{token}`. 새 토큰이 시험을 통과해야 바꾼다(실패하면 옛 토큰 유지) |
| `PUT /dns/providers/{id}` | SA | `{name}`(앞뒤 공백 제거, 1~100자) → `{provider}`. 이름만 바꾼다(토큰 그대로) |
| `DELETE /dns/providers/{id}` | SA | 204. 그 연결을 쓰던 도메인은 클러스터 목록에 남고 공급자만 떨어진다(웹의 레코드 표시·서버 연결도 지움) |
| `GET /dns/providers/{id}/domains` | SA | 가져올 도메인 `{items:[{name, hasZone, connected, registered?}]}`. `hasZone:false`는 DNS가 그 공급자에 없음. `connected`는 이 연결을 이미 붙임. `registered`는 클러스터 도메인 목록에 있음(보관함을 읽지 못하면 없음) |
| `GET /dns/domains` | 로그인 | `{items:[{domain, unicode?, provider:{id, vendor, name}\|null, registered, hosts, certificates, defaultTtl, assignments, addedBy, addedAt, myNames?}], cluster: true}`. SA는 클러스터 목록 전부에 웹 연결을 붙여 본다(`hosts`는 그 아래 (호스트, 알고리즘) 링크 수, `certificates`는 링크가 있는 인증서 수, `registered:false`는 목록에서 빠졌는데 웹 연결만 남은 것). 다른 사용자는 보관함을 읽지 못하므로 자기 작업 공간이 배정된 연결 도메인만, 그 배정만, `myNames`(바꿀 수 있는 이름 범위)와 함께 본다 |
| `POST /dns/domains` | SA | `{domain, provider?, defaultTtl?(3600), assignments?:[{tenant, names:["shop","*.shop"]}]}` → 201 `{domain, linked}`. 이름은 A-label로 바꾼다(422 `public-suffix`·`invalid-domain`). 목록에 없으면 `add-domain`을 보낸다. `provider`를 주면 그 공급자에 영역이 있는지 보고 연결도 저장한다(이미 등록된 도메인이면 연결만). `linked`는 등록으로 링크를 얻은 인증서 수. 이미 등록됐고 provider가 없거나, 이미 연결됐으면 409 `exists`. DNS가 다른 곳이면 409 `zone-elsewhere` |
| `PUT /dns/domains/{domain}` | SA | `{defaultTtl, assignments}`. 공급자가 없으면 409 `no-provider` |
| `DELETE /dns/domains/{domain}` | SA | `remove-domain`을 보내고 웹 연결도 지운다 → `{unlinkedHosts, unlinkedCertificates}`(빼기 전 그 아래 링크 수, 링크를 모두 잃은 인증서 수). 링크가 있어도 거절하지 않는다. 공급자의 레코드와 바꾼 기록은 남는다. 목록에도 연결에도 없으면 404 |
| `PUT /dns/domains/{domain}/provider` | SA | `{provider}` → `{domain}`. 등록된 도메인에 공급자를 붙이거나 바꾼다(영역 확인은 POST와 같음, 기본 TTL·배정은 그대로). 목록에 없으면 404 |
| `DELETE /dns/domains/{domain}/provider` | SA | → `{domain}`. 공급자만 뗀다. 도메인은 목록에 남는다 |
| `GET /dns/domains/{domain}/records` | 배정된 작업 공간 구성원 / SA | 매번 공급자에서 읽음. `{items:[{name, type, ttl, records, fingerprint, managed, outside, writable}], orphans, capabilities, readAt}`. 작업 공간 사용자는 배정 범위 안의 이름만 본다. `outside`는 Sfc가 만들지 않았고 어느 작업 공간에도 배정되지 않은 레코드 |
| `POST /dns/domains/{domain}/plan` | 배정 범위의 작업 공간 관리자 / SA | `{upsert:[{name, type, ttl?, records:[{content, priority?}]}], delete:[{name, type}], outside?, tenant?, app?}` → `{changes:[{name, type, before, after, fingerprint, tenant, outside}], problems}`. 아무것도 바꾸지 않는다 |
| `POST /dns/domains/{domain}/apply` | 같음 | plan 본문 + `{opId, basis:{"name\|type": fingerprint}, revertOf?}` → `{history}`. `revertOf`는 `revert`가 돌려준 기록 ID로, 새 기록의 `history.revertOf`에 남는다(그 도메인에 없는 ID면 422) |
| `GET /dns/domains/{domain}/history` | 구성원 / SA | 바꾼 기록 `{items:[{id, at, username, tenant, changes:[{name, type, before, after}], result, error, snapshot, revertOf}]}`(최신 200개). 작업 공간 사용자는 자기 작업 공간 몫만 |
| `POST /dns/domains/{domain}/history/{id}/revert` | 그 작업 공간 관리자 / SA | 바꾸기 전 값으로 되돌리는 **요청 본문**을 돌려준다. 그대로 plan → apply 한다 |
| `DELETE /dns/domains/{domain}/history/{id}` | SA | 바꾼 기록 지우기(사용자가 지울 때까지 보관) |
| `GET /dns/domains/{domain}/propagation?name=&type=` | 배정된 작업 공간 구성원(그 이름이 범위 안) / SA | 반영 확인. `{name, type, want:[값], resolvers:[{kind:"authoritative"\|"public", server, values, fresh, ttlLeft?, error?}], checkedAt}`. `want`는 지금 공급자 값이다. 권한 서버는 공개 해석기(1.1.1.1)가 본 그 도메인의 NS(4개까지)이고 재귀 없이 묻는다. 공개 해석기는 1.1.1.1·8.8.8.8·9.9.9.9. `fresh`는 값이 `want`와 같음, `ttlLeft`는 공개 해석기 답의 남은 TTL(초), `error`는 그 서버에 묻지 못함(`unavailable` 등). 값 형식은 레코드 문자열과 같다(MX·SRV는 "우선순위 내용"). 웹 앱이 직접 묻는다(sfcd 무관). 공급자의 `capabilities.propagation`이 아니면 409 `not-supported` |
| `GET /dns/domains/{domain}/servers` | 배정된 작업 공간 구성원 / SA | 연결된 서버(웹 몫, 캔버스 ExtDomainDetail). `{items:[{node, listen, addresses, addressSource: node\|manual, linked, autoRemove, reach?:{ok, at, error?}, state: in-dns\|removed\|not-linked, isolated?, missing?}], revision, changes?:{upsert, delete}, staged?, partial?}`. SA는 외부망 게이트웨이가 켜진 서버 전부(sfcd `ingresses`에서 매번 읽음. `listen`은 외부망 공유 수신 주소의 포트, `node` 주소는 그 수신 주소 중 와일드카드가 아닌 IP이고 와일드카드뿐이면 비어 있어 `manual`로 넣는다)와 바뀔 레코드를 본다. `removed`는 `autoRemove`인데 서버가 격리됐거나 외부망 게이트웨이가 없어진 것(`missing`). 그 밖의 사용자는 연결한 서버만 저장된 그대로 보고(`partial: true`, 서버 주소·격리는 모름) `changes`가 없다 |
| `PUT /dns/domains/{domain}/servers/{node}` | SA | `{linked, addressSource?, addresses?(manual, 공개 IPv4·IPv6 1~8개), autoRemove?(기본 true), revision}` → GET과 같은 모양. 409 `stale`, 외부망 게이트웨이가 없는 서버 404, 마지막 서버를 끊으면 422 `last-server`, 잘못된 주소 422. 영역은 바꾸지 않는다. `changes`는 Sfc가 만든 A·AAAA 레코드 이름마다 `in-dns`인 서버 주소로 맞추는 바꿀 내용(IPv4 → A, IPv6 → AAAA, 주소가 없는 종류는 지움, 남이 만든 레코드는 건드리지 않음)이고 `staged`는 그 개수다. 적용은 이것을 `plan`·`apply`에 그대로 보낸다. 연결이 하나도 없으면 바꿀 내용도 없다. `autoRemove`는 지금 바꿀 내용에서 빼는 것까지이고 스스로 적용하지는 않는다 |
| `POST /dns/domains/{domain}/servers/check` | 배정된 작업 공간 구성원 / SA | `{node?, addresses?}` → `{items:[{node, ok, at, error?}]}`. 웹 앱에서 각 주소의 :443으로 TCP 연결을 연다(공개 주소만, 5초). node가 없으면 연결한 서버 전부이고 결과를 `reach`로 남긴다. `error`는 읽는 사람의 언어로 만든다("198.51.100.50: 공개 주소가 아님", 영어 "…: not a public address"; 저장은 코드와 주소·포트). `addresses`(저장 전 시험)는 SA가 node 하나에만 쓰고 남기지 않는다 |
| `GET /dns/domains/{domain}/snapshots` | SA | 공급자 되돌리기 지점(`capabilities.snapshots`일 때만, 아니면 501) |
| `POST /dns/domains/{domain}/snapshots/{id}/restore` | SA | `{confirm:"<도메인>"}`. 공급자가 그 지점으로 되돌린다 |

바꾸기 규칙:
- 단위는 `name+type` 묶음이다. upsert는 그 묶음 전체를 주어진 값으로 바꾸므로 두 번 적용해도 결과가 같다. `ttl`을 비우면 도메인 기본 TTL.
- 작업 공간 사용자는 그 작업 공간 **관리자**이고 이름이 배정 범위 안일 때만 바꾼다(아니면 403 `out-of-range`). 보기 권한만 있으면 읽기만 된다.
- SA가 Seafield Cluster 밖 레코드(`outside`)를 바꾸려면 `outside:true`를 보내야 한다(확인 다이얼로그, 아니면 409 `outside`). 바꾼 뒤에도 Seafield Cluster 레코드로 표시하지 않는다.
- apply는 영역을 다시 읽어 각 묶음의 지문이 `basis`와 다르면 아무것도 바꾸지 않고 409 `zone-changed`(다른 곳에서 바뀜, 바뀐 묶음 목록 포함). 공급자가 미리 검사를 지원하면 문제가 있을 때 422 `dns-invalid`.
- 공급자를 부르기 **전에** 바꾼 기록을 `unknown`으로 저장하고, 결과에 따라 `applied`·`failed`로 바꾼다. 응답이 끊기면(`dns-unavailable`) `unknown`으로 남으며, 기록 화면에서 지금 값과 전후 값을 비교한다. 같은 `opId`를 다시 보내면 공급자를 다시 부르지 않고 저장된 기록을 돌려준다(본문이 다르면 409 `op-conflict`).
- 적용이 끝난 upsert는 `dns-managed`에 "Sfc가 만든 레코드"(작업 공간·앱·바꾼 사람·지문)로 표시하고, delete는 표시를 지운다. 표시만 남고 레코드가 없으면 `orphans`.

아직 없는 것: 서버 공개 주소·도메인에 서버 연결·자동 빼기(`dns-servers`), 배포 화면의 '배포가 끝나면 레코드 만들기'.
