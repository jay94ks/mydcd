## 상태 검사 스크립트와 정책 (UI-90·91)

**sfcd 몫**: 스크립트 목록(`lifecycles`)과 규칙 전부(정책이 원본·모듈 잠금을 허용하는지, 기록 CAS, 지우기는 은퇴했고 아무도 고정하지 않은 버전만), 원본 올리기·컴파일 검사, 원본 글 읽기, 쓰는 앱 읽기, 빌드 서버의 이미지 검사. **웹 몫**: `lifecycles` 페이지를 스크립트별로 묶기, payload 만들기, 정책을 일부만 바꿀 때 나머지 채우기, 목록 정렬, 서명 전 안내(아래 409·422). 웹은 원본 글도 정책도 저장하지 않는다. REQ-39~41은 가짜 어댑터에서만 동작한다.

`lifecycles`는 ManageServices(작업 공간 관리자)가 있어야 읽힌다. 구성원은 403이다. 응답은 `{op}`, `opId` 규칙은 공유 자원 만들기와 같다(target `lifecycle/<이름>`, 정책은 `lifecycle-policy`).

| 끝점 | 뜻 |
|---|---|
| `GET /t/{t}/lifecycle-scripts` | `{items:[L], policy:{configured, enabled, revision}}` |
| `GET /t/{t}/lifecycles?after=` | sfcd `lifecycles` 쪽 그대로(`control.LifecycleEntry`: `key, recordRevision, name?, sourceRevision?, source?, active?, deleted?, policy?`). 작업 공간은 URL에 있어 행에 `tenant`가 없다. 화면은 위 `lifecycle-scripts`를 쓴다 |
| `GET /t/{t}/lifecycles/{name}?revision=` | `{script: L, revision, source, sourceAvailable, usedBy, usedByAvailable}`. revision 기본은 활성 버전, 없으면 지우지 않은 가장 새 버전. `source`는 그 버전 글, 읽을 수 없으면 `null`·`sourceAvailable:false`. `usedBy` = `[{id, revision, kind(app-binding/build-job), app, service, standalone?, node}]`(REQ-41 `PublicRead` `lifecycle-uses`), 읽을 수 없으면 `null`. 없는 이름·버전은 404 |
| `PUT /t/{t}/lifecycles/{name}` | `{opId, source, node?, lock?:[{path, version, zip?(base64)}], expected?}` → 원본을 provider 서버에 올리고 검사(REQ-39, docs/reference/lifecycle-sources.md) → `put-lifecycle-script`. 순서: `zip`이 있는 잠금 모듈마다 `lifecycle-module-stage`를 먼저 하고, 그다음 `lifecycle-source-stage`를 한다. 모두 같은 서버·같은 upload ID로 보낸다. `node`가 없으면 sfcd가 고르고, 응답의 Node를 나머지 단계에 쓴다. upload ID는 사용자·opId에서 정해지므로 같은 opId로 다시 보내도 같다. 응답을 잃으면(sfcd 오류가 아닌 연결 오류) 다시 보내지 않고 `*-recover`로 원 기록을 읽는다. ZIP은 본문 한도(8 MiB) 안이어야 하고, 모양이 핀과 다르면 422 `invalid`. provider에 없는 잠금 모듈을 `zip` 없이 고르면 422 `module-missing`. 새 이름은 expected 0, 있는 이름은 L.recordRevision(기본: 지금 값). `lock`은 정책 `resolver.modules` 중에서 고른다(아니면 422 `invalid`). 정책이 없거나 꺼져 있으면 409 `policy-disabled`. 컴파일 오류는 422 `compile-error`, `error.diagnostics:[{line, column, message}]`(1부터, 위치가 없으면 0). 올린 버전이 활성이 된다 |
| `POST /t/{t}/lifecycles/{name}/retire` | `{opId, revision, expected?}` → `retire-lifecycle-script`(비활성). 이미 비활성이면 409 `not-active` |
| `DELETE /t/{t}/lifecycles/{name}` | `{opId, revision, expected?}` → `delete-lifecycle-script`. 활성이면 409 `active`(먼저 retire), 쓰는 앱·빌드 작업이 있으면 409 `in-use`, 이미 지웠으면 409 `deleted`. 웹이 쓰는 곳을 읽을 수 없을 때 sfcd가 거절하면 op `failed` |
| `GET /t/{t}/lifecycle-policy` | `{configured, policy: P}`. 정책이 없으면 첫 PUT이 시작할 기본값(켜짐, 해석 실행만, 동시 4개, 5초, CPU 0.5, 64 MiB, PID 32, 출력·probe 64 KiB, connect·healthz, 원본 캐시 16 MiB) |
| `PUT /t/{t}/lifecycle-policy` | `{opId, expected?, enabled?, build?, execution?, resolver?, compiledCacheBytes?}` → `set-lifecycle-policy`(정책 전체). 보내지 않은 부분은 지금 값(없으면 기본값). `build`·`execution`·`resolver`는 각각 통째로 바뀐다. 목록은 데몬이 정렬한다. Expected 기본 = P.revision(처음은 0). 규칙에 어긋나면 422 `invalid-policy`(메시지에 첫 위반). 빌드 서버의 이미지는 sfcd가 검사한다(op `failed`) |

L = `{name, recordRevision, activeRevision(0 = 없음), latestRevision, versions:[{revision, active, deleted, digest(원본 sha256 hex), length, modules:[{path, version}]}]}`. 기록을 바꿀 때마다(올리기·retire·delete) recordRevision이 1 오르고, 새 버전의 revision은 올린 뒤의 recordRevision이다.

P = `{tenant, revision, enabled, build:{nodes, targets, image, toolchain, maxJobs, nanoCPU, memoryBytes, workspaceBytes, artifactBytes, timeoutMS}, execution:{maxConcurrent, timeoutMS, nanoCPU, memoryBytes, maxPIDs, outputBytes, probeBytes, capabilities}, resolver:{allowPackages, denyPackages, modules:[{path, version, digest(모듈 zip sha256 hex), length}], sourceCacheBytes}, compiledCacheBytes}`. PUT 본문도 같은 이름을 쓴다. 빌드 서버가 없으면(`nodes` 비움) 해석 실행만 하며 `image`·`toolchain`·`targets`는 비운다. `capabilities`는 connect·dependency·exec·file·healthz 중 1~5개다.

go.lock 자리: 따로 없다. 스크립트는 파일 하나(package checker, `func Check(ctx, lifecycle.Request, lifecycle.Probe) (lifecycle.Result, error)` 하나)이고, 외부 모듈은 `lock`에 정책이 허용한 모듈을 고르는 것으로 잠근다.

가짜 시드: shop 정책(rev 1, 켜짐, 모듈 `golang.org/x/text@v0.21.0`), `http-ready` 버전 1(은퇴)·2(활성, php-shop/web이 씀), recordRevision 3. payments는 정책 없음.

원본 글은 `lifecycle-source` 페이지(24 KiB씩, Offset/Next)를 다 이어 붙여 digest·UTF-8을 확인한 뒤 보여 준다.
