## 웹 앱 설정 (UI-C1, 시스템 관리자)

시스템 관리자 여부는 요청마다 mydcd `whoami`로 다시 확인한다. 아니면 403 `denied`.

| 끝점 | 뜻 |
|---|---|
| `GET /system/settings` | `{settings, defaults, info:{version, schema, dbBytes, dbPath, socket, connected, mydcdVersion?:{version, commit?, buildTime?, protocol}, restorePending}, seal:{state, ready, reason, keySource?, dir?, fingerprint?, next?:{fingerprint}, files?, kinds:[{kind, count, modified}]}}`. 봉인 파일은 종류별 개수와 마지막으로 바뀐 날만, 값·이름은 없음. `socket`은 mydcd 소켓 경로, `connected`는 지금 새 연결이 열리는지(로그인 없이 열고 바로 닫음). `mydcdVersion`은 그 연결에서 로그인 전에 읽은 REQ-48 `server-version`(접속한 mydcd 자신의 것: `protocol`은 MYDCP 판 번호의 문자열, `buildTime`은 RFC 3339)이고, 읽지 못하면 없다. 웹이 자기 컨테이너(`container`)를 알 방법이 없어 그 칸은 없다. `keySource`는 `env`(`MYDC_WEB_SEAL_KEY`) 또는 `file`(`-seal-key-file`), `fingerprint`·`next.fingerprint`는 키가 아니라 봉인 파일 머리글에 이미 있는 키 식별자(키 해시)를 `abcd…wxyz`로 줄인 것이다. `next`는 `MYDC_WEB_SEAL_KEY_NEXT`로 띄웠을 때만 있다 |
| `PUT /system/settings` | `{settings:{sessionMaxHours 0..720, sessionIdleMinutes 0..1440, opRetentionDays 1..3650, auditRetentionDays 30..3650, notificationRetentionDays 1..3650, allowKeyLogin?, maxSessionsPerUser 0..50, webhookDeliveryRetentionDays 0..3650, mcpCallRetentionDays 0..3650}}`. 범위 밖이면 422. 0인 세션 값은 끔(로그인 상한 = MYDCP 세션 만료). `allowKeyLogin`을 빼면 허용, 보관 기간 0은 기본값(웹훅 전달 30일, MCP 호출 90일). 바꾼 전후 값이 설정 변경 기록에 남음 |
| `POST /system/seal/reset` | `{confirm:"reset"}` → 봉인 상태. 봉인 파일을 모두 지우고 지금 키로 새로 시작한다(옛 키를 잃었을 때). 값은 되살릴 수 없다. 봉인이 정상(`ready`)이면 409 `seal-ready`로 거부, 키 없이 띄운 데몬이면 409 `no-key` |
| `GET /system/backup` | 웹 데이터 전체(`web.db`)를 한 파일로 내려받기. 봉인 파일은 넣지 않는다 |
| `POST /system/restore` | 본문 = 백업 파일(최대 512 MiB) → 202 `{restorePending, bytes}`. 웹 데이터 파일이 맞는지·형식 판이 맞는지 확인하고 `web.db.restore`로 둔다. **다음 시작 때** 바뀌고, 바뀐 파일은 `web.db.before-restore-<시각>`으로 남는다. 아니면 422 `invalid` |
| `DELETE /system/restore` | 대기 중인 되살리기 취소 → 204 |

세션 시간: `sessionMaxHours`는 새 로그인의 만료를 앞당기고, `sessionIdleMinutes`는 브라우저 요청이 그만큼 없던 로그인을 끝낸다(`idle`). 자동 새로고침(주기 조회, SSE 다시 잇기)은 `X-MyDC-Background: 1` 헤더를 붙이고, 이 요청은 활동으로 세지 않는다. 보관 기간은 매시간 정리에 쓴다(작업 기록·끝난 로그인 행 = `opRetentionDays`, 설정 변경 기록, 알림). 웹훅 전달 기록과 MCP 호출 기록 보관 기간은 지금은 값만 저장하고, 각 기능이 붙을 때 정리에 쓴다.

한 사람의 로그인 수: `maxSessionsPerUser`가 1 이상이면 새 로그인으로 그 수를 넘을 때 그 사람의 가장 오래된 로그인부터 끝낸다(`session-limit`, 그 로그인의 스트림·터미널도 끝남). 값을 낮추면 저장할 때 바로 적용한다. 0은 제한 없음.

봉인 키 바꾸기: 데몬을 `MYDC_WEB_SEAL_KEY`(지금 키)와 `MYDC_WEB_SEAL_KEY_NEXT`(새 키, 또는 `-seal-key-next-file`)로 시작하면 모든 봉인 파일을 새 키로 다시 봉인한다. 중간에 멈춰도 같은 두 키로 다시 시작하면 남은 파일만 마저 바꾼다. 끝나면 새 키를 `MYDC_WEB_SEAL_KEY`로 바꾸고 옛 키를 뺀다. 화면에서 키 바꾸기를 시작하는 끝점은 없다(새 키는 환경 변수나 파일로만 들어오고, 들어오면 시작할 때 이미 바꾼다). 화면은 `seal.next`로 바꾸는 중임을 보이고 이 안내를 보여 준다.

자동 백업(UI-C1): 웹 데이터를 gzip으로 묶은 뒤 **웹 봉인 키(`MYDC_WEB_SEAL_KEY`)로 봉인해** 작업 공간의 고정 데이터 저장소에 `mydc-web-backups/web-YYYY-MM-DDTHHMMZ.db.gz.sealed`(UTC) 파일로 쓴다. 파일 쓰기·목록·지우기·읽기는 REQ-28 `volume-file-put`·`-list`·`-delete`·`-get` op라(아래 '데이터 저장소 파일') 그 저장소에 누가 손댈 수 있는지는 mydcd가 정한다. 쓰기는 봉인한 바이트의 길이·digest로 계획을 받고(덮어쓰기 허용, 256 MiB까지) 한 번 스트림한다. 결과를 모르면 그 실행은 `volume-file-unknown`으로 끝나고 다음 실행이 새 파일을 쓴다. 백업 파일에는 웹 데이터 전체(작업 기록, 설정 변경 기록, 내린 앱의 app.yaml 등)가 들어가지만, 봉인돼 있어 그 저장소를 읽을 수 있는 사람도 키 없이는 내용을 볼 수 없다(파일 크기와 만든 시각만 보인다). 봉인 파일(`secrets/`)은 들어가지 않는다.

봉인 형식: 봉인 파일과 같은 AES-256-GCM. 머리글 `mydc-web-seal\0`·판 1·키 식별자 8바이트, 그 뒤 nonce 12바이트와 암호문. 추가 인증 데이터는 머리글과 `blob:web-backup`이라 봉인 파일과 서로 바꿔 끼울 수 없다. 키는 bbolt·로그·op 어디에도 남기지 않는다. 봉인이 준비되지 않았으면(`GET /system/seal`의 `ready:false`) 백업을 쓰지도 풀지도 않는다(503 `seal-unavailable`). 평문으로 대신 쓰지 않는다.

키와 백업: 백업은 그 파일을 쓴 키로만 풀린다. 다른 설치로 옮기거나 디스크를 잃은 뒤 되살리려면 `MYDC_WEB_SEAL_KEY` 값(보통 Docker secret)을 웹 밖에 따로 보관해 두었다가 새 설치에 같은 값으로 넣는다. 웹은 키를 화면이나 API로 내보내지 않는다. 봉인 키를 바꾸는 동안(`_NEXT`와 함께 띄운 동안)은 옛 키로 쓴 백업도 풀리지만, 옛 키를 뺀 뒤에는 풀리지 않는다. 키를 바꾼 뒤에는 바로 한 번 백업을 돌리고, 옛 백업이 필요하면 옛 키를 함께 보관한다.

| 끝점 | 뜻 |
|---|---|
| `GET /system/auto-backup` | `{enabled, at, keep, tenant?, volume?, prefix:"mydc-web-backups/", running, sealed:true, sealReady, last?:{at, ok, bytes?, path?, error?, by?}, next?, updatedBy?, updatedAt?}`. `at`은 서버 시각 `HH:MM`, `next`는 켜져 있을 때 다음 예정 시각. `sealReady`가 false면 지금 돌려도 503이다. `account`는 예약 실행이 서명할 자동 작업 계정 이름(없으면 빠짐), `accountId`는 그 계정의 사용자 ID(처음 로그인에 성공한 뒤부터, `file-grants`에 쓴다). `granted`는 그 계정이 이 저장소의 `mydc-web-backups/`(또는 그 위 폴더)를 위임받았고 계정이 켜져 있는지(REQ-49 `PublicRead` `volume-file-grants`를 부른 사람의 세션으로 읽음, AccountEnabled·VolumePresent가 둘 다 참일 때). 계정이 없거나, 저장소를 안 골랐거나, mydcd가 그 사람에게 목록을 주지 않으면 빠진다(화면은 '확인 못 함'). PUT 응답에도 붙는다 |
| `PUT /system/auto-backup` | `{enabled, at, keep(1..365), tenant, volume}` → 같은 모양. 볼륨은 앱이 소유하지 않은 고정 데이터 저장소여야 한다(아니면 422, 없으면 404). 켜려면 tenant·volume이 필요하다. 바꾼 전후가 설정 변경 기록에 남는다. 폴더 위임(`file-grants`)은 따로 낸다 |
| `POST /system/auto-backup/run` | → 202 `{running:true}`. **로그인한 관리자의 세션으로** 지금 한 번 쓰고, 보관 개수를 넘은 오래된 `web-*.db.gz.sealed`를 지운다. 쓰기·지우기 op는 그 관리자의 작업 기록에 사유 `web-backup`으로 남는다. 끝나면 `last`가 바뀐다. 이미 도는 중이면 409 `running`, 저장소를 안 골랐으면 409 `not-configured`, 봉인이 준비되지 않았으면 503 `seal-unavailable` |
| `POST /system/restore-from` | `{tenant, volume, path}` → `POST /system/restore`와 같은 202 `{restorePending, bytes}`. 관리자 세션으로 그 파일을 읽어 봉인을 풀고 gzip을 풀어 확인한 뒤 `web.db.restore`로 둔다. path는 `mydc-web-backups/` 바로 아래 파일이어야 한다(아니면 422). 이 웹의 봉인 키로 풀리지 않으면(다른 키, 봉인 안 된 파일, 손상) 422 `seal-key`, 봉인이 준비되지 않았으면 503 `seal-unavailable` |

예약 실행: 매일 `at`에 아래 자동 작업 계정으로 로그인해서 쓴다(`last.by` = 그 계정). 그 계정이 저장소에 쓸 수 있는지는 mydcd가 정한다(작업 공간 구성원·폴더 위임). 계정이 없으면 `last = {ok:false, error:"automation-account-missing"}`, 로그인이 안 되면 `error:"automation-login-failed: <코드>"`, 이미 도는 중이면 `running`, 봉인이 준비되지 않았으면 `seal-unavailable`로 남기고, 설정한 관리자에게 알림(`web-backup`)을 보낸다. mydcd가 쓰기를 거부하면 그 오류가 `last.error`에 남는다. 백업 목록·내려받기·지우기는 데이터 저장소 파일 끝점(`/t/{t}/volumes/{name}/files`…)을 그대로 쓴다.

자동 작업 계정: 사람이 없을 때 서명할 일(예약 백업, 이후 인증서 갱신·장애 자동 대응)을 웹이 평범한 mydcd 계정으로 로그인해서 한다. 키 쌍은 웹이 만들고, 개인키(Ed25519 seed)는 봉인 파일 `automation-key`에만 두며 브라우저·bbolt·로그·op로 내보내지 않는다. bbolt에는 계정 이름과 공개키만 둔다. 공개키를 그 계정의 로그인 수단으로 등록하는 일(`put-user`, Method `private-key`), 동작 범위·키 전용(`PUT /users/{u}/scope`), 작업 공간 구성원은 관리자가 자기 세션으로 서명하는 보통 op다. 웹은 그 계정에 따로 권한을 주지 않고, 무엇을 할 수 있는지는 mydcd가 정한다. 시스템 관리자만 부른다.

| 끝점 | 뜻 |
|---|---|
| `GET /system/automation` | `{configured, sealReady, username?, userId?(처음 로그인에 성공한 뒤), publicKey?(hex 32B), fingerprint?("SHA256:xxxxxxxx…xxxxxxxx"), createdBy?, createdAt?, lastCheck?:{at, ok, user?, error?, reason?}}`. `lastCheck`는 마지막 로그인(확인·예약 실행) |
| `PUT /system/automation` | `{username, rotate?}` → 같은 모양. 처음이거나, 이름이 바뀌었거나, `rotate:true`면 새 키 쌍을 만든다. 아니면 키를 그대로 둔다. 응답의 `publicKey`를 `put-user`로 그 계정에 등록한다. 바꾼 옛 키는 mydcd에서 따로 지울 때까지 등록돼 있다. 이름 형식이 틀리면 422, 봉인이 준비되지 않았으면 503 `seal-unavailable`. 설정 변경 기록 `automation`에 이름과 지문만 남는다 |
| `POST /system/automation/check` | → `{ok, user?, username?, systemAdmin?, error?}`. 지금 그 키로 로그인해 `whoami`를 묻는다. `error`는 mydcd 코드(`denied` = 등록되지 않음·무효화·키 전용 아님 등) 또는 `automation-account-missing`. 계정을 만들지 않았으면 409 `not-configured` |
| `DELETE /system/automation` | → 204. 계정 정보와 봉인된 키를 지운다. 예약 작업은 멈춘다. mydcd에 등록된 공개키는 관리자가 따로 지운다 |
