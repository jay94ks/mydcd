## 이미지 신뢰 출처

작업 공간이 어느 저장소의 이미지를 믿는지(`set-trust`)를 보고 바꾼다. 받을 때마다 신뢰를 검사하는 것은 sfcd다. 웹은 sfcd가 준 목록을 보여 주고, 뺄 규칙 때문에 어떤 이미지가 허용 규칙을 모두 잃는지 셀 뿐이다.

- `GET /t/{t}/image-trust` → `{tenant, revision, rules:[{index, registry, repository, origin, pull, uses, only}], uses, untrusted}`.
  - `origin`: `default`(Docker Hub `**`, 새 작업 공간 기본) / `builtin`(이 작업 공간의 내장 저장소 주소) / `direct`(직접 넣은 것). 외부 저장소 등록이 생기면 `external`이 더해진다.
  - `pull`: `registry-credential`(내장 저장소 자격) / `anonymous`(로그인 없이 받음).
  - 규칙과 사용은 sfcd `PublicRead` `image-trust`의 페이지 `Rules`와 `Image` 행이고, `revision`은 그 페이지의 TenantRevision이다(`set-trust`의 Expected).
  - `uses`: `[{app?, deployment?, service?, standalone?, image, rules:[규칙 번호]}]`. 규칙마다 그 규칙이 허용하는 사용, `only`는 그 규칙만 허용하는 사용의 수(빼면 신뢰되지 않음). 맨 위 `untrusted`는 지금 어느 규칙도 허용하지 않는 사용이다.
- `POST /t/{t}/image-trust/preview` `{remove:[{registry, repository}]}` → `{affected:[use]}`: 이 규칙들을 빼면 허용 규칙을 모두 잃는 지금의 사용. 함께 더할 규칙은 계산에 넣지 않는다(넉넉히 알린다).
- `PATCH /t/{t}/image-trust` `{opId, add:[{registry, repository}], remove:[{registry, repository}], expected?}` → `set-trust {Tenant, Add, Remove}`. 바뀐 규칙만 보낸다. Expected 기본은 `revision`. 저장소 이름이 소문자 host[:port]가 아니거나, 같은 규칙이 겹치거나, add·remove가 둘 다 비면 422. 이미 있는 규칙을 더하거나 없는 규칙을 빼면 낡은 목록에서 만든 변경이라 op가 실패(CAS)한다. 응답은 `{op}`.

이미지 참조 확인 (UI-3F 이미지 고르기, REQ-31 mock `image-resolve`, 작업 공간 Read):

- `POST /t/{t}/images/resolve` `{ref}` → `{input, ref, registry?, registryKind, source?, digest?, pinned?, mediaType?, platforms:[{platform?, digest}], trusted, rules:[{registry, repository}], reason?, code?}` (sfcd 실제 `image-resolve`, `docs/reference/image-resolution.md`). sfcd가 참조를 정규화하고(`docker.io/library/…`, 태그 기본 `latest`), 이 작업 공간이 받아 올 출처를 고르고, 신뢰 출처 규칙을 검사한 뒤 digest를 푼다. 미리 보기일 뿐이고 실제로 받을 때 sfcd가 다시 검사한다. `registryKind`는 `builtin`(내장 저장소), `external`(외부 저장소 정의, 이름은 `source`), `unknown`(로그인 없이 받는 신뢰된 공개 저장소). `registry`는 주소(host[:port])다. `code`가 없으면 풀린 것이고, 있으면 sfcd 코드를 소문자·`-`로 바꾼 값이다: `untrusted`(신뢰 규칙에 없음, 저장소에 묻지도 않음), `source-revoked`(맞는 외부 정의가 지워졌거나 꺼짐), `source-not-ready`(외부 정의에 읽는 서버가 없음), `unauthorized`, `denied`, `not-found`, `unavailable`, `unsupported`, `timeout`, `cancelled`, `metadata-budget`, `image-budget`, `invalid-ca`, `invalid-credential`, `invalid-source` 등. `trusted:false`면 `reason`이 붙고 `rules`는 이 작업 공간의 신뢰 규칙이다. 여러 플랫폼 묶음이면 `digest`는 묶음 자체이고 `platforms`에 `os/arch[/variant]`별 digest가 있다. `pinned`는 정의에 넣을 `authority/repository@digest`(태그 없음). 참조 형식이 틀리거나 비었으면 422 `invalid-ref`.
